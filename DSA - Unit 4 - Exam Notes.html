1.1

What is a Tree? Terminology

The vocabulary every later section in this unit assumes without re-explaining.

A tree is a hierarchical, non-linear data structure used to organize data so that it is easy to navigate and search. It is a collection of nodes connected by edges, arranged so that there is exactly one path from the root to every other node. Unlike a linear structure (array, linked list, stack, queue) where each element has at most one predecessor and one successor, a tree's elements are arranged across multiple levels — which is precisely why it is called a non-linear data structure.

The topmost node is the root; every other node is reached by following edges downward from it. A node's child nodes are the nodes immediately below it and connected to it; that node is, in turn, their parent. Each child can have its own children, so the structure repeats recursively at every level — this recursive self-similarity is why trees are usually defined and processed recursively.

Formally, a tree consists of a root node together with zero or more disjoint subtrees T1, T2, …, Tk, each connected to the root by a single edge. This recursive definition is exactly why every traversal and construction algorithm later in this unit is written recursively: "process the root, then recurse on each subtree" is a direct restatement of the definition itself.

Why trees? Linear vs hierarchical data (UNIT4 deck, p2–4)Arrays, lists, stacks and queues keep data in a sequence (A → B → C → D). Real-world data often has parent → child relationships — a university has departments (CSE, ECE, ME, CI, CD, CY), each with its own classes and staff — and a sequence cannot show that structure. A tree is the non-linear structure that can: nodes joined by edges, with one topmost node called the root, growing downward. In the deck's example tree A is the root; B, C, D are its children and siblings of one another; A is their parent; E and F are leaves.

1.2

Tree Representation & Types by Number of Children

How a node is represented in code, and the three-way classification that follows directly from how many children a node is allowed.

Representing a tree node

Since a node may have any number of children, the most general node representation keeps one pointer per possible child:

struct Node { int data; struct Node* first_child; struct Node* second_child; struct Node* third_child; ... struct Node* nth_child; };

This works, but wastes space when most nodes have far fewer children than the maximum, and the number of pointers must be fixed at compile time. It motivates restricting how many children a node may have — which is exactly how trees are classified below.

Fig 2. Tree data structures classified by number of children: Binary, Ternary, N-ary (Generic).
TypeRuleNotes
Binary TreeEach node has at most 2 children.By far the most common in practice — BST, Binary Heap, AVL are all binary trees. Parts 2–5 of this guide are mostly about binary trees (Part 1 covers general and N-ary trees, and §1.4–1.5 show how any tree or forest reduces to a binary tree).
Ternary TreeEach node has at most 3 children.Children are usually distinguished as "left", "mid", "right".
N-ary / Generic TreeEach node may have any number of children (no fixed bound), stored as a list of child references with no duplicates.A file-system directory tree is a natural N-ary tree.

Why trees matter

Trees are the natural fit whenever data is intrinsically hierarchical. A computer's file system is an N-ary tree (a folder's children are its files and subfolders); the DOM of an HTML page is a tree rooted at <html> with <head> and <body> as children, each of which has its own children tags. The basic operations available on any tree are create, insert, delete, search, and traversal (visiting every node in a specific order) — the last of these is developed fully in Part 3.

What "N-ary" means, and where N-ary trees are used (UNIT4 deck, p5–7)

An N-ary tree allows each node to have at most N children — "at most" means a node may have 0 (a leaf), 1, 2, …, up to N children, never more. N = 2 gives the binary tree, N = 3 a ternary tree, N = 4 a 4-ary tree. The value of N fixes the maximum branching; restricting N from "any number" down to 2 is exactly what the conversion of §1.4 achieves without losing information.

ApplicationWhy an N-ary tree fits

Menus and navigationa menu item branches into several options
DOM / HTML structurea parent element may have many child elements
AI search and game treesa state can lead to several possible next states
Organisation hierarchiesone manager or unit has many direct subordinates
Tries and prefix structuresa node branches on many possible symbols

1.3

Tree Properties: Edges, Depth, Height, Degree

The four measurements every "describe this tree" or "find this node's X" question is built from.

PropertyDefinition
Number of edgesA tree with N nodes always has exactly N−1 edges — every node except the root is connected to its parent by exactly one edge, and there is only one path between any two nodes.
Depth of a nodeThe length of the path from the root down to that node — equivalently, the number of edges on that path. The root has depth 0.
Height of a nodeThe length of the longest path from that node down to a leaf in its subtree. A leaf has height 0.
Height of the treeThe height of the root — i.e. the longest root-to-leaf path in the whole tree.
Degree of a nodeThe number of subtrees (children) attached to it. A leaf always has degree 0. The degree of the tree is the maximum degree over all its nodes.
Depth looks up, height looks down Depth is measured from the root down to a node (root = 0). Height is measured from a node down to its deepest leaf (every leaf = 0). For the root itself, depth = 0 but height = height of the whole tree — they only coincide by accident, never by definition.
Fig 3. Height and depth at every level of a perfect binary tree of height 3 (15 nodes).
RVCE CIE-II · 3 Jan 2021 · Q1.52 marks
For the tree below, find: (i) height of node 7, (ii) common ancestors of nodes 10 and 11, (iii) depth of node 6, (iv) level of node 9.
Fig 4. General (non-binary) tree — node 7 has three children.
Solution
  1. Height of node 7 = length of the longest downward path from 7 to a leaf in its subtree. 7's children are 2 (leaf), 10 (leaf), and 6; 6's children are 5 and 11 (both leaves). Longest path: 7 → 6 → 5 (or 11), 2 edges. Height(7) = 2.
  2. Common ancestors of 10 and 11: ancestors of 10 are {root 2, node 7}; ancestors of 11 are {root 2, node 7, node 6}. Intersection = {2, 7}.
  3. Depth of node 6 = edges from root to it: 2 → 7 → 6. Depth(6) = 2.
  4. Level of node 9 = edges from root to it: 2 → 5 → 9. Level(9) = 2.

Verified by simulating the tree's parent/child map in code and computing each quantity generically, rather than by eye.

RVCE Quiz-II · 2 Dec 2024 · Q1.41 mark
The maximum height of a binary tree with n nodes is ______.
Solution

Height is maximised when the tree is as "unbalanced" as possible — a fully skewed (degenerate) tree where every node has exactly one child, forming a single chain of n nodes and n−1 edges. Maximum height = n − 1 (verified for n = 1, 4, 7 by direct simulation, giving heights 0, 3, 6 respectively — each exactly n−1). This is the opposite extreme from a balanced tree (§2.3), whose height is only O(log n).

1.4

N-ary Tree to Binary Tree Conversion

The left-child / right-sibling (LCRS) representation: any tree, whatever its fan-out, fits in a node with exactly two links.

Why convert?

In an N-ary tree a node may have any number of children, so a node either needs a variable-length array of child pointers or a fixed array sized for the worst case (wasteful). Restricting every node to at most two links gives the binary-tree node struct — one data field and two pointers — and lets every binary-tree algorithm (traversals, construction, threading) be reused on arbitrary trees. The standard trick is the Left-Child / Right-Sibling representation: the two pointers are re-interpreted so that nothing about the original tree is lost.

The conversion rules

  1. First child becomes the LEFT child. Connect each node to its leftmost (first) child using its left link.
  2. Next sibling becomes the RIGHT child. Connect the children of the same parent from left to right, each to the next, using right links.
  3. Remove the extra parent-to-child links. Only the first child keeps a direct link from the parent; every other child is reachable through the sibling chain.
MnemonicLEFT = first child  |  RIGHT = next sibling. The root of the N-ary tree has no siblings, so the root of the binary tree has no right child.

Going back, and what is preserved

  • Binary → N-ary: a node's left child is its first child; follow the right links from that left child to collect all the remaining children. The conversion is therefore one-to-one and reversible (round trip verified in code).
  • Node count is unchanged (7 nodes before and after); the N-ary tree has N−1 = 6 edges, and the binary tree has the same 6 links. Every node uses 2 pointer slots, so a tree of n nodes has n + 1 NULL pointers in this representation (here 8).
  • Traversals map directly: the preorder of the N-ary tree equals the preorder of its binary representation (A, B, E, F, C, D, G), and the postorder (children first, then the node) of the N-ary tree equals the inorder of the binary representation (E, F, B, C, G, D, A). Both were confirmed by code.
  • Height can grow: a node with many children becomes a long right-leaning sibling chain, so the binary tree is usually deeper than the N-ary tree (here height 4 against 2).

C node and linking function

Not in your materials — added for syllabus completenessThe deck gives the pictorial rules only; the struct and the addChild routine below are standard LCRS code added so the representation can actually be built.
struct Node { int data; struct Node *firstChild; // LEFT link: first child struct Node *nextSibling; // RIGHT link: next sibling }; struct Node* newNode(int d) { struct Node *n = (struct Node*) malloc(sizeof(struct Node)); n->data = d; n->firstChild = n->nextSibling = NULL; return n; } // append 'child' as the LAST child of 'parent' void addChild(struct Node *parent, struct Node *child) { if (parent->firstChild == NULL) { parent->firstChild = child; return; } struct Node *s = parent->firstChild; while (s->nextSibling != NULL) s = s->nextSibling; // walk the sibling chain s->nextSibling = child; }

Time to add a child is O(number of existing children). Keeping a lastChild pointer per parent makes it O(1) at the cost of one more field.

1.5

Forests & Forest to Binary Tree

A forest is a set of disjoint trees; the same left-child / right-sibling idea turns the whole forest into one binary tree.

Definition and properties

A forest is a collection of zero or more disjoint trees. Each tree has its own root, the trees share no nodes, and there is no edge joining one tree to another. If a forest has k (non-empty) trees it has k roots and k connected components. Removing the root of a tree leaves a forest — the forest of that root's subtrees — and a graph-theory example is the spanning forest of a graph that is not connected.

Checking the edge count on the deck's forest A(B,C), D(E), F(G,H): trees have 3, 2 and 3 nodes, hence 2 + 1 + 2 = 5 edges = 8 − 3 (verified in code).

Converting a forest to a binary tree

  1. Convert each tree of the forest to binary form with the LCRS rules of §1.4.
  2. Treat the roots as siblings: link the root of the 2nd tree as the right child of the 1st tree's root, the 3rd root as the right child of the 2nd, and so on.
  3. The root of the first tree is the root of the resulting binary tree; the roots of the other trees form its right-sibling chain.

Designing Trees for Real-World Hierarchical Data

File systems and organisational charts: choosing the node fields, the representation, and the traversal that answers each question.

Not in your materials — added for syllabus completenessDesigning custom trees for file systems and organisational charts is a self-learning topic in the syllabus and is not covered in any of your decks; this section is written from scratch.

A design recipe

  1. Find the parent-child relation. Folder contains file/folder; manager has direct reports. If every item has exactly one parent, the data is a tree (several independent hierarchies form a forest, §1.5).
  2. Choose the node payload. What each item stores: name, type (file/directory), size, employee id, title.
  3. Choose the representation. Fixed small fan-out → array of child pointers. Unbounded fan-out (folders, managers) → first-child / next-sibling (§1.4): two pointers per node regardless of the number of children.
  4. Map each question to a traversal. Questions that need the children's answers first (total size, head-count) are postorder; listings that print a node before its contents (ls -R, an org-chart printout) are preorder with the depth used for indentation; "how many levels down?" is depth/height (§4.3).

File system tree

Types of Binary Trees by Structure

Full / strictly binary, degenerate, and skewed — classified by the shape each node's children take, not by how full each level is.

TypeRule
Full / Strictly Binary TreeEvery node has either 0 or 2 children — never exactly 1. Equivalently: every non-leaf node has two children. Also called a proper binary tree.
Degenerate (Pathological) TreeEvery internal node has exactly one child. Performance-wise this behaves exactly like a linked list — every operation that would be O(log n) on a balanced tree degrades to O(n).
Skewed Binary TreeA degenerate tree that leans consistently one direction: left-skewed (every node's single child is a left child) or right-skewed (every node's single child is a right child).
Fig 9. Types of binary trees by structure: Full, Degenerate, Left-skewed, Right-skewed.
Full / Strictly Binary Tree = the same thing "Full binary tree", "strictly binary tree", and "proper binary tree" are three names for one definition: every node has 0 or 2 children, never 1. If an exam question asks you to define a "strictly binary tree" (as in the RVCE CIE-II paper), this is the definition to give — it is not a separate concept from the Full Binary Tree above.
Left child ≠ right child (UNIT4 deck, p9–11)In a binary tree position matters: a node has at most two children, called the left and right child, and each child can itself be the root of another binary tree. A root A with left child B and right child C is a different tree from A with left child C and right child B, although the two have the same parent-child pairs. (This is what separates a binary tree from a general tree with two unordered children.)

Types of Binary Trees by Level-Completion

Complete and Perfect binary trees — classified by how filled each level is, independent of the structural types in §2.1.

Complete Binary Tree

A binary tree is complete if every level is completely filled except possibly the last, and the last level's nodes are all pushed as far left as possible. A complete binary tree looks like a full binary tree with two relaxations: not every level needs to be entirely full, and the last leaf need not have a right sibling.

"Almost Complete Binary Tree" is the same definition Some exam papers (RVCE CIE-II Q6b) ask for an "almost complete binary tree" as if it were a distinct term. In standard usage — and in this course — it is synonymous with the Complete Binary Tree defined here: every level full except possibly the last, with the last level's nodes filled left to right. If asked to define it, give this exact definition and this figure as the example.

Perfect Binary Tree

A binary tree is perfect if every internal node has exactly two children and every leaf sits at the same level. A perfect binary tree of height h has exactly 2h+1 − 1 nodes, and its leaf count is always one more than its internal-node count: L = I + 1.

2.3

Balanced Binary Trees

A structural guarantee that keeps tree operations fast — the property every self-balancing tree (AVL, Red-Black) is built to preserve.

A binary tree is balanced if its height is O(log n) for n nodes — informally, no branch is allowed to grow much longer than any other. The standard node-local test is: for every node, the depth-difference between its left and right subtree is at most 1, i.e. |height(left subtree) − height(right subtree)| ≤ 1. Balanced trees are valuable because they guarantee O(log n) time for search, insert, and delete — the whole reason self-balancing structures like the AVL tree exist is to enforce exactly this property after every insertion or deletion (AVL's internal rotation mechanics are a separate module, not covered here).

2.4

Binary Search Trees & the C Implementation

The one binary tree whose shape encodes an ordering — plus the full C code for insert, search, delete, and traversal, and five worked BSTs. Creation from a list, the successor/predecessor deletion variants and display continue in §2.5.

The BST property

A Binary Search Tree is a binary tree with an ordering rule attached: for every node, every key in its left subtree is smaller than the node's key, and every key in its right subtree is larger. Both subtrees must themselves be binary search trees. This single rule is what makes search, insert, and delete all achievable in O(height) time — at every node you know immediately which subtree a target key must be in, without examining the other one.

Fig 12. The BST property: every left-subtree key is smaller than the root, every right-subtree key is larger — applied recursively at every node.

Searching, minimum and maximum (tree_traversal deck, p8–14)

The ordering "provides an ordering among keys so that search, minimum and maximum can be done fast"; without it every key would have to be compared. Search algorithm: (1) start at the root; (2) compare the target with the node's key; (3) if equal the item is found — if it is a leaf and not equal, it is not found; (4) if the target is smaller search the left subtree; (5) if larger search the right subtree; (6) repeat on the chosen subtree. Each comparison discards one subtree, so the cost is O(height) — O(log n) for a balanced tree against O(n) in a linked list (and O(n) in the worst case for a skewed BST). The smallest key is the leftmost node, the largest key the rightmost node.

The rule must hold at every node Checking only the root's two children is not enough: in a valid BST every subtree is itself a BST (deck p18: at node 30, 20 < 30 < 40; at node 80, 70 < 80 < 90 — the same rule at every node). A tree with, say, a key larger than the root hiding in the left subtree is not a BST even if each parent-child pair looks ordered. There must be no duplicate keys.

Applications (UNIT4 deck p20): fast searching; keeping ordered data retrievable in sorted order; dynamic insertions and deletions that preserve order; range queries; symbol tables / dictionaries (see §2.6). Creation, deletion cases and display are developed further in §2.5.

Full C implementation

The struct, node creation, BST insertion, all three recursive traversals, minimum-finding, search, and deletion (handling all three deletion cases) together:

// node structure struct BinTree { int key; struct BinTree *left, *right; }; // create a new node struct BinTree* newNodeCreate(int value) { struct BinTree* temp = (struct BinTree*) malloc(sizeof(struct BinTree)); temp->key = value; temp->left = temp->right = NULL; return temp; } // BST-insert a value, respecting the ordering property struct BinTree* insertNode(struct BinTree* node, int value) { if (node == NULL) return newNodeCreate(value); if (value < node->key) node->left = insertNode(node->left, value); else if (value > node->key) node->right = insertNode(node->right, value); return node; } // preorder / inorder / postorder — see Part 3 for the general form void preOrder(struct BinTree* root){ if(root){ printf(" %d ",root->key); preOrder(root->left); preOrder(root->right);} } void inOrder(struct BinTree* root){ if(root){ inOrder(root->left); printf(" %d ",root->key); inOrder(root->right);} } void postOrder(struct BinTree* root){ if(root){ postOrder(root->left); postOrder(root->right); printf(" %d ",root->key);} } // leftmost node = smallest key in a BST/subtree struct BinTree* findMin(struct BinTree* root) { if (root == NULL) return NULL; if (root->left != NULL) return findMin(root->left); return root; } // O(height) search using the BST property struct BinTree *searchNode(struct BinTree* root, int target) { if (root == NULL || root->key == target) return root; if (root->key < target) return searchNode(root->right, target); return searchNode(root->left, target); } // delete: 3 cases — leaf, one child, two children struct BinTree* delete(struct BinTree* root, int x) { if (root == NULL) return NULL; if (x > root->key) root->right = delete(root->right, x); else if (x < root->key) root->left = delete(root->left, x); else { if (root->left == NULL && root->right == NULL) { free(root); return NULL; } // case 1: leaf else if (root->left == NULL || root->right == NULL) { // case 2: one child struct BinTree* temp = (root->left == NULL) ? root->right : root->left; free(root); return temp; } else { // case 3: two children struct BinTree* temp = findMin(root->right); // inorder successor root->key = temp->key; root->right = delete(root->right, temp->key); } } return root; }
Why three cases? Deleting a leaf just detaches it. Deleting a node with one child means the parent can simply adopt that child in its place. Deleting a node with two children is the hard case: neither child can take the deleted node's exact spot without breaking the BST property, so the node's value is replaced by its inorder successor (the smallest key in its right subtree, found via findMin), and that successor is then deleted from its original position — which is guaranteed to be case 1 or 2, never case 3 again.

BST Operations: Creation, Insertion, Deletion & Display

Creation = repeated insertion

A BST is created by starting from an empty tree and inserting the keys one by one, in the given order. To insert a key, start at the root; go left if the key is smaller than the current node, right if larger, and when a NULL link is reached, hang the new node there. The same key list in a different order can give a different tree, because the first key always becomes the root. (Duplicates are not allowed; the code in §2.4 ignores them.)

// iterative insert (same result as the recursive insertNode of section 2.4) struct BinTree* insertIter(struct BinTree *root, int value) { struct BinTree *node = newNodeCreate(value), *cur = root, *parent = NULL; while (cur != NULL) { // walk down to a NULL link parent = cur; if (value < cur->key) cur = cur->left; else if (value > cur->key) cur = cur->right; else { free(node); return root; } // duplicate: ignore } if (parent == NULL) return node; // tree was empty if (value < parent->key) parent->left = node; else parent->right = node; return root; }

Search, minimum and maximum

Search follows the same left/right decisions as insertion and stops on equality or on a NULL link (not found). The smallest key is the leftmost node and the largest is the rightmost node. In a BST of height h each operation takes O(h): O(log n) for a balanced tree, O(n) for a skewed one.

Deletion: the three cases

First locate the node, then delete it so that the BST property is preserved:

CaseNode to deleteAction
1Leaf (no children)Remove it; the parent's link becomes NULL.
2One childBypass it: the parent's link is set to the node's only child.
3Two childrenCopy into the node the key of its inorder successor (the minimum of the right subtree) or its inorder predecessor (the maximum of the left subtree), then delete that replacement node from its original place (it has at most one child, so this is case 1 or 2).

Both replacement rules keep the order valid: the inorder successor is the next larger key (larger than everything on the left, not larger than anything else on the right), and the predecessor is the next smaller key.

Preorder, Inorder, Postorder — Policy & Algorithms

The three ways to linearise a tree, and why each one is named the way it is.

A tree traversal visits every node exactly once, in a well-defined order. Unlike a linear structure (which has exactly one natural traversal order), a tree admits multiple useful orders because at every node there is a choice of when to visit the node itself relative to its two subtrees. All three traversals below always visit the left subtree before the right subtree — they differ only in when the root itself is visited relative to those two.

3.3

Level-Order Traversal Using a Queue

Breadth-first: visit the tree level by level, left to right — the one traversal that needs a queue instead of recursion.

Not in your materials — added for syllabus completenessLevel-order traversal is listed under the self-learning topics but does not appear in your decks.

Idea

Preorder, inorder and postorder are depth-first: they dive down one subtree completely before starting the next, and the call stack (or an explicit stack) remembers where to come back to. Level-order (breadth-first) visits all nodes at depth 0, then all nodes at depth 1, and so on, each level from left to right. That "oldest discovered node first" rule is exactly a FIFO queue.

  1. If the tree is empty, stop. Otherwise enqueue the root.
  2. While the queue is not empty: dequeue a node and visit it.
  3. Enqueue its left child (if any), then its right child (if any).
#define MAX 100 struct BinTree { int key; struct BinTree *left, *right; }; void levelOrder(struct BinTree *root) { struct BinTree *queue[MAX]; int front = 0, rear = 0; // empty when front == rear if (root == NULL) return; queue[rear++] = root; // enqueue the root while (front < rear) { struct BinTree *n = queue[front++]; // dequeue printf("%d ", n->key); // visit if (n->left) queue[rear++] = n->left; if (n->right) queue[rear++] = n->right; } } // level-by-level (prints a new line per level): process exactly 'size' nodes per round void levelByLevel(struct BinTree *root) { struct BinTree *queue[MAX]; int front = 0, rear = 0; if (root == NULL) return; queue[rear++] = root; while (front < rear) { int size = rear - front; // nodes currently on this level for (int i = 0; i < size; i++) { struct BinTree *n = queue[front++]; printf("%d ", n->key); if (n->left) queue[rear++] = n->left; if (n->right) queue[rear++] = n->right; } printf("\n"); } } // build a binary tree by inserting into the first vacant slot in level order (complete tree) struct BinTree* insertLevel(struct BinTree *root, int v) { struct BinTree *n = (struct BinTree*) malloc(sizeof(struct BinTree)); n->key = v; n->left = n->right = NULL; if (root == NULL) return n; struct BinTree *queue[MAX]; int front = 0, rear = 0; queue[rear++] = root; while (front < rear) { struct BinTree *c = queue[front++]; if (c->left == NULL) { c->left = n; return root; } queue[rear++] = c->left; if (c->right == NULL) { c->right = n; return root; } queue[rear++] = c->right; } return root; }

Morris Traversal (Inorder Without Recursion or Stack)

Inorder in O(n) time and O(1) extra space, by temporarily threading each node's inorder predecessor back to it.

Not in your materials — added for syllabus completenessMorris traversal is a self-learning topic that is not in your decks. It is the temporary, self-restoring version of the permanent threads of §6.

The problem it solves

Recursive inorder uses O(h) stack space; the iterative version uses an explicit stack of the same size. A threaded tree (§6) avoids the stack by storing "thread" pointers, but needs extra tag bits and a modified structure. Morris traversal gets the same effect on an ordinary binary tree: while walking, it borrows the NULL right pointer of a node's inorder predecessor to remember the way back, and removes that pointer again afterwards, so the tree is left exactly as it was.

Algorithm (inorder)

  1. Set cur = root. Repeat while cur != NULL:
  2. If cur has no left child: visit cur, then move right (cur = cur->right; this may follow a thread back to an ancestor).
  3. Otherwise find the inorder predecessor pred of cur: the rightmost node in cur's left subtree (stop if pred->right is NULL or already equals cur).
  4. If pred->right == NULL: set the thread pred->right = cur, then go left (cur = cur->left).
  5. If pred->right == cur: the left subtree is finished. Remove the thread (pred->right = NULL), visit cur, then go right.
void morrisInorder(struct BinTree *root) { struct BinTree *cur = root, *pred; while (cur != NULL) { if (cur->left == NULL) { printf("%d ", cur->key); // no left subtree: visit and go right cur = cur->right; } else { pred = cur->left; // find inorder predecessor while (pred->right != NULL && pred->right != cur) pred = pred->right; if (pred->right == NULL) { // first visit: make the thread pred->right = cur; cur = cur->left; } else { // second visit: left side done pred->right = NULL; // restore the tree printf("%d ", cur->key); cur = cur->right; } } } } // preorder variant: identical, but visit cur when the thread is CREATED // if (pred->right == NULL) { printf("%d ", cur->key); pred->right = cur; cur = cur->left; }

4.1

Constructing a Binary Tree from Preorder + Inorder

Given any two different traversals of the same binary tree, the tree can (usually) be reconstructed uniquely. This is the preorder+inorder recipe.

Problem: given the preorder and inorder traversal of a binary tree, reconstruct the unique tree that produces both. The key insight: preorder always starts with the root, and once you know the root, its position within inorder splits the remaining keys into exactly the left subtree (everything before it) and the right subtree (everything after it) — because inorder visits left, then root, then right. The matching prefix/suffix of the preorder array gives each subtree's own preorder, and the same idea is applied recursively.

  • The first element of preorder is the root of the (sub)tree.
  • Find that value's position i in inorder. Everything left of i is the left subtree's inorder; everything right of i is the right subtree's inorder.
  • If the left subtree has X elements, the next X elements of preorder (after the root) are the left subtree's preorder; the remaining elements are the right subtree's preorder.
  • Recurse on (left preorder, left inorder) and (right preorder, right inorder); attach the results as root.left and root.right.

    Answer — decision rule

    Yes, uniquely — for a BST specifically, unlike an arbitrary binary tree. A general binary tree genuinely needs two traversals (as in this whole section) because preorder alone doesn't say which side of the root each later key belongs on. A BST removes that ambiguity: its ordering property means every later key is already comparable to the root — any key smaller than the root belongs in the left subtree, any key larger belongs in the right, with no need to consult inorder at all. The reconstruction is just repeated BST insertion: insert the preorder sequence, in order, into an empty BST using the ordinary insertNode from §2.4, and the result is guaranteed to be the original tree.

    Constructing a Binary Tree from Postorder + Inorder

    The mirror image of §4.1: the root now comes from the end of the traversal, not the start.

    The same idea as §4.1 applies, with one change: postorder always ends with the root (left, right, root), so the root is the last element of postorder rather than the first. Once the root is found in inorder and the left/right inorder groups are known, the matching prefix/suffix of postorder (not counting the root itself, which is dropped from the end) gives each subtree's postorder.

  • The last element of postorder is the root of the (sub)tree.
  • Find that value's position i in inorder → left inorder = everything before i, right inorder = everything after.
  • If the left subtree has X elements, the first X elements of postorder are the left subtree's postorder; the next Y elements (before the final root element) are the right subtree's postorder.
  • Recurse on each (postorder, inorder) pair and attach as root.left / root.right.

    Height, Depth, Leaf / Internal Nodes and Node Count

    Recursive and iterative C code for every basic tree measurement, with all values computed on the Fig 13 tree.

    Not in your materials — added for syllabus completenessThe decks define these terms (§1.3) but give no code for measuring them; both the recursive and the iterative versions are written here.

    Definitions used (same conventions as §1.3)

    • Depth of a node = number of edges from the root to it (root depth 0). Height of a node = number of edges on the longest downward path to a leaf (leaf height 0). Height of the tree = height of the root. (Some books count nodes instead of edges, adding 1 — state your convention in the exam.) Height of an empty tree is defined as −1.
    • Leaf = node with no children. Internal node = node with at least one child. Node count = leaves + internal nodes.
    • For any binary tree, with n0 leaves, n1 nodes with one child and n2 nodes with two children: n0 = n2 + 1, and n = n0 + n1 + n2.

    Recursive versions

    int height(struct BinTree *t) { // edges; empty tree = -1 if (t == NULL) return -1; int hl = height(t->left), hr = height(t->right); return 1 + (hl > hr ? hl : hr); } int countNodes(struct BinTree *t) { return t == NULL ? 0 : 1 + countNodes(t->left) + countNodes(t->right); } int countLeaves(struct BinTree *t) { if (t == NULL) return 0; if (t->left == NULL && t->right == NULL) return 1; return countLeaves(t->left) + countLeaves(t->right); } int countInternal(struct BinTree *t) { // nodes with at least one child if (t == NULL || (t->left == NULL && t->right == NULL)) return 0; return 1 + countInternal(t->left) + countInternal(t->right); } // depth of key x in a BST (-1 if absent): walk down from the root counting edges int depthOf(struct BinTree *t, int x) { int d = 0; while (t != NULL && t->key != x) { t = (x < t->key) ? t->left : t->right; d++; } return t == NULL ? -1 : d; }

    Iterative versions

    Height needs level information, so it uses the level-order queue of §3.3 and counts how many rounds it takes to drain it. Node, leaf and internal counts only need some traversal order, so a stack (or the same queue) is enough.

    Lowest Common Ancestor (LCA)

    The deepest node that has both given nodes in its subtree — a one-loop answer in a BST, a recursion in a general binary tree.

    Not in your materials — added for syllabus completenessLCA is a self-learning topic that is not in your decks; both versions below are standard algorithms, with every answer checked in code.

    Definition

    The lowest common ancestor of nodes a and b in a rooted tree is the deepest node that is an ancestor of both. A node counts as an ancestor of itself, so if a is an ancestor of b then LCA(a, b) = a. (Assumption throughout: both keys are present in the tree.) Equivalently, it is the last node shared by the root-to-a path and the root-to-b path.

    Version 1 — in a BST: use the ordering

    Start at the root. If both keys are smaller than the current node, the LCA lies in the left subtree; if both are larger, in the right subtree. The first node at which the keys split (one ≤ node ≤ the other) is the LCA. No recursion and no stack: O(h) time, O(1) space.

    struct BinTree* lcaBST(struct BinTree *root, int a, int b) { while (root != NULL) { if (a < root->key && b < root->key) root = root->left; // both in left subtree else if (a > root->key && b > root->key) root = root->right; // both in right subtree else return root; // split point (or one equals root) } return NULL; }

    Expression Trees: Definition & Traversal ↔ Notation

    A binary tree that encodes an arithmetic expression — where each traversal order corresponds to a familiar notation.

    An expression tree is a binary tree in which every internal (non-leaf) node holds an operator, and every leaf holds an operand. Each operator node's two children are the sub-expressions it combines. Because operator precedence and parenthesisation are captured entirely by the tree's shape (an operator deeper in the tree binds tighter), evaluating or converting the expression becomes a traversal problem rather than a parsing problem.

    Constructing an Expression Tree from Postfix

    A stack-based algorithm that mirrors postfix evaluation exactly — but builds a tree instead of a number.

    Scan the postfix expression left to right, one character at a time:

  • If the character is an operand, push a new leaf node holding it onto the stack.
  • If the character is an operator, pop the top two nodes off the stack — the first pop becomes the right child, the second pop becomes the left child — build a new node holding the operator with those two children, and push that new node back onto the stack.

    • At the end, exactly one node remains on the stack: the root of the expression tree.

    Worked trace — infix A*B+C-D/E, postfix AB*C+DE/−.
    StepScanActionStack after (bottom → top)
    1Apush leaf AA
    2Bpush leaf BA, B
    3*pop B, A → build A*B, push itA*B
    4Cpush leaf CA*B, C
    5+pop C, A*B → build (A*B)+C, push itA*B+C
    6Dpush leaf DA*B+C, D
    7Epush leaf EA*B+C, D, E
    8/pop E, D → build D/E, push itA*B+C, D/E
    9−pop D/E, A*B+C → build (A*B+C)−(D/E), push it(A*B+C)−(D/E)

    Expression Trees: Implementation & Evaluation (Arithmetic and Boolean)

    Evaluating a tree by postorder recursion, a complete C implementation (build from postfix + traverse + evaluate), and boolean expression trees.

    Not in your materials — added for syllabus completenessThe decks stop at construction and the three traversals; tree evaluation, the full C implementation and boolean expression trees are added here.

    Evaluation = postorder

    To evaluate an expression tree, the values of both subtrees must be known before the operator at the node can be applied — which is exactly the postorder rule (left, right, then the node). Leaves (operands) return their own value; an internal node evaluates its left and right subtrees recursively and applies its operator to the two results. The tree encodes the precedence and brackets, so no extra rules are needed. Time O(n), stack space O(h).

    #include <stdio.h> #include <stdlib.h> #include <ctype.h> struct ETNode { char op; double val; struct ETNode *left, *right; }; // op == 0 means operand struct ETNode* mk(char op, double v, struct ETNode *l, struct ETNode *r) { struct ETNode *n = (struct ETNode*) malloc(sizeof(struct ETNode)); n->op = op; n->val = v; n->left = l; n->right = r; return n; } // build from a postfix string of single-digit operands, e.g. "23*21-/541-*+" struct ETNode* buildFromPostfix(char *p) { struct ETNode *st[100]; int top = -1; for (; *p; p++) { if (isdigit(*p)) st[++top] = mk(0, *p - '0', NULL, NULL); // operand: push a leaf else { // operator: pop two, build, push struct ETNode *r = st[top--]; // FIRST pop = right child struct ETNode *l = st[top--]; // second pop = left child st[++top] = mk(*p, 0, l, r); } } return st[top]; // one node left: the root } void inorder(struct ETNode *t) { if (t) { if (t->op) printf("("); inorder(t->left); if (t->op) printf("%c", t->op); else printf("%g", t->val); inorder(t->right); if (t->op) printf(")"); } } void preorder(struct ETNode *t) { if (t) { if (t->op) printf("%c ", t->op); else printf("%g ", t->val); preorder(t->left); preorder(t->right); } } void postorder(struct ETNode *t) { if (t) { postorder(t->left); postorder(t->right); if (t->op) printf("%c ", t->op); else printf("%g ", t->val); } } double evaluate(struct ETNode *t) { // postorder: operands first, then the operator if (t->op == 0) return t->val; // leaf double a = evaluate(t->left), b = evaluate(t->right); switch (t->op) { case '+': return a + b; case '-': return a - b; case '*': return a * b; case '/': return a / b; // caller must avoid b == 0 } return 0; } int main() { struct ETNode *root = buildFromPostfix("23*21-/541-*+"); printf("infix : "); inorder(root); printf("\n"); printf("prefix : "); preorder(root); printf("\n"); printf("postfix: "); postorder(root); printf("\n"); printf("value = %g\n", evaluate(root)); return 0; }

    Boolean expression trees

    A boolean expression tree has the same shape rules, with logical operators in the internal nodes (AND, OR, XOR, NOT) and the variables or constants 0/1 (false/true) at the leaves. Two points differ from arithmetic trees:

    • NOT is unary: its node has just one child (by convention the right child, so that postfix C NOT pops one operand). Everything else is binary.
    • Evaluation is again postorder, but with logic instead of arithmetic. Short-circuit evaluation may skip a subtree: 0 AND x is 0 and 1 OR x is 1 without evaluating x — an optimisation preorder-style recursion makes easy.

    The tree for (A AND B) OR (NOT C) has postfix A, B, AND, C, NOT, OR and prefix OR, AND, A, B, NOT, C — built with the same stack algorithm, where NOT pops one operand.

    struct BNode { char op; // 'A' = AND, 'O' = OR, 'N' = NOT, 'V' = variable/constant leaf int val; // leaf value 0 or 1 struct BNode *left, *right; }; int evalBool(struct BNode *t) { switch (t->op) { case 'V': return t->val; case 'N': return !evalBool(t->right); // unary: only the right child is used case 'A': return evalBool(t->left) && evalBool(t->right); // short-circuit AND case 'O': return evalBool(t->left) || evalBool(t->right); // short-circuit OR } return 0; }

    6.1

    Threaded Binary Trees: Motivation & Types

    A plain binary tree wastes roughly half its pointers on NULL — threading puts them to work.

    Drawbacks of a plain binary tree

    • Roughly 50% of node pointers are NULL — every leaf wastes both pointers, every single-child node wastes one.
    • Traversal takes more time — recursion (or an explicit stack) is required to visit every node in order.
    • Finding the inorder successor or predecessor of a given node takes more time — with only child pointers available, there is no direct way to jump to "the next node in sorted order" without a traversal from the root.
    Fig 43. A plain binary tree: every × marks a NULL pointer that threading will reclaim.

    The fix: threading

    A threaded binary tree replaces NULL pointers with threads — links to that node's inorder predecessor or successor — so the traversal order becomes directly reachable without recursion or a stack. The tree is anchored by a head node, a sentinel whose pointer holds the address of the root, giving the very first and last nodes' otherwise-missing threads somewhere valid to point.

    TypeWhat gets threaded
    In-threadedNULL pointers replaced by inorder predecessor/successor threads (the most common — covered in detail in §6.2)
    Pre-threadedNULL pointers replaced by preorder predecessor/successor threads
    Post-threadedNULL pointers replaced by postorder predecessor/successor threads

    Within in-threading there are two independent choices, which can be applied separately or together:

    VariantRule
    Left-threadedEvery NULL left pointer becomes a thread to that node's inorder predecessor; right pointers stay ordinary tree links.
    Right-threadedEvery NULL right pointer becomes a thread to that node's inorder successor; left pointers stay ordinary tree links.
    Double-threadedBoth — every NULL pointer, left or right, becomes a thread. Gives O(1) access to both the predecessor and successor of any node.
    Trade-off Threading trades a small amount of extra bookkeeping (every node needs a tag bit to distinguish "this is a real child pointer" from "this is a thread") for O(1) predecessor/successor access and stack-free traversal — valuable whenever traversal happens far more often than insertion/deletion.

    Iterative inorder traversal using a right-threaded tree

    This directly answers "design an iterative routine for inorder traversal of a right-threaded binary tree" (and is exactly what a C program to implement a threaded binary tree needs to provide): walk to the leftmost node first, then repeatedly follow the thread if the current node has no real right child, or descend to the leftmost node of its right subtree otherwise.

    // isThread is a tag bit stored per node: true if 'right' is a thread, not a real child void inorderThreaded(Node* root) { Node* cur = leftMost(root); while (cur != NULL) { printf("%d ", cur->data); if (cur->isThread) cur = cur->right; // follow the thread directly to the successor else cur = leftMost(cur->right); // otherwise descend to the next real subtree's leftmost node } } Node* leftMost(Node* n) { if (n == NULL) return NULL; while (n->left != NULL) n = n->left; return n; }

    No stack, no recursion — every step is O(1) amortized, giving O(n) total for a full traversal, exactly like the recursive version but without the call-stack overhead. This is the practical payoff threading is built for.

    Threaded Binary Tree in C: Header Node, Construction & Traversals

    The double-threaded tree with a header node as drawn in the threaded-tree deck, with its node struct, construction routine and inorder / preorder traversals.

    Node and header node

    A double-threaded node needs two extra tag bits so that "real child" and "thread" can be told apart. In the deck's convention lbit = 1 (rbit = 1) means the left (right) pointer is a real child; 0 means it is a thread. A new node starts with both bits 0 and both pointers NULL.

    struct node { int data; struct node *left, *right; int lbit; // 1: left is a child, 0: left is a thread (to inorder predecessor) int rbit; // 1: right is a child, 0: right is a thread (to inorder successor) };

    The tree hangs from a header node (sentinel, data 999 in the deck): head->left points to the root (lbit = 1), head->right points to the header itself (rbit = 1), the left thread of the first (leftmost) node and the right thread of the last (rightmost) node both point to the header. Because of this, no pointer in the structure is ever NULL, and a traversal can detect its end by reaching head again.

    Inorder and preorder traversal of a threaded tree

    No recursion and no stack. Inorder: from the leftmost node (follow real left links), print it; then, while the node's right link is a thread, follow it and print the successor; when the right link is a real child, step to it and again run to its leftmost node. Stop on returning to the header. Preorder: print each node while descending along real left links; at the end of a left chain follow right threads (those nodes were already printed) until a real right child is found.

    void inorder(struct node *head) { struct node *ptr = head->left; do { while (ptr->lbit != 0) ptr = ptr->left; // run to the leftmost node printf("%d ", ptr->data); while (ptr->rbit == 0) { // right link is a thread: successor ptr = ptr->right; if (ptr == head) return; printf("%d ", ptr->data); } ptr = ptr->right; // real right child: continue from there } while (ptr != head); } void preorder(struct node *head) { struct node *ptr = head->left; do { while (ptr->lbit != 0) { printf("%d ", ptr->data); ptr = ptr->left; } // print on the way down printf("%d ", ptr->data); while (ptr->rbit == 0) { // thread leads to an already-printed ancestor ptr = ptr->right; if (ptr == head) return; } ptr = ptr->right; } while (ptr != head); }

    Tracing threading on a given tree: exam method

    1. Write the inorder sequence of the tree.
    2. For every node with a NULL left pointer, thread it to its predecessor (the node just before it in that sequence; the header if it is first).
    3. For every node with a NULL right pointer, thread it to its successor (next in the sequence; the header if it is last).
    4. Left-in-threaded does step 2 only; right-in-threaded step 3 only; double-threaded both (see the three diagrams in §6.2).
