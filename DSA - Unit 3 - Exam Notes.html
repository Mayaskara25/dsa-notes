1.1

Queue Concept, FIFO & ADT

FIFO concept · abstract data type · enqueue, dequeue, front, rear

Definition

A queue is an ordered list in which insertions take place at one end, called the rear, and deletions take place at the opposite end, called the front. Only these two ends take part in the standard queue operations: you cannot read, insert or remove anything in the middle. Because the element that was inserted first is also the first one to be deleted, a queue is called a FIFO (First-In, First-Out) structure. It models every real waiting line: a ticket counter, a printer, a bus stop.

Fig 1. A queue: insertions happen only at the rear, deletions only at the front, so elements leave in the order they arrived (FIFO).

FIFO principle

FIFO means that service order equals arrival order. If 10, 20, 30, 40 are enqueued in that order, they are dequeued as 10, 20, 30, 40. This is the opposite of a stack, where the last element in is the first one out (LIFO). Rear is insert-only and front is delete-only: the two ends have different jobs, which is why a queue needs two position markers (front and rear) while a stack needs only one (top).

Queue as an Abstract Data Type

An abstract data type (ADT) specifies what a data structure does without saying how it is stored. The queue ADT is a collection of items together with the following operations. The textbook of the course (Horowitz, Sahni and Anderson-Freed) names them CreateQ, IsEmptyQ, IsFullQ, AddQ and DeleteQ; they correspond to the names used elsewhere in this guide.

The four named operations

Enqueue (AddQ): (1) check whether the queue is full; (2) advance rear; (3) store the new item at queue[rear]. The queue grows at the rear and existing items keep their relative order. Dequeue (DeleteQ): (1) check whether the queue is empty; (2) read the item at front; (3) advance front. The queue shrinks at the front, and the next item automatically becomes the new front. Front identifies the element that will be removed next; rear marks the end where the next element will be inserted (or, in many implementations, the last inserted element — see the clarification below).

Clarifying an ambiguous point in the source The decks say that rear "marks the position where the next element will be inserted", while the code on the same decks does rear++; queue[rear] = item;, which means rear holds the index of the last inserted element. Both readings appear in textbooks. This guide uses the code's convention (rear = index of the last element, initially -1) wherever it matters, and says so explicitly in each implementation.

Error conditions

  • Queue overflow — an enqueue on a full fixed-size queue. Report "Queue Full" and do not insert.
  • Queue underflow — a dequeue (or front/rear) on an empty queue. Report "Queue Empty" and do not remove anything.
  • Wrap-around — in a circular queue the indices are updated modulo the capacity; the empty and full conditions must be defined carefully for the chosen representation (section 1.3).

1.2

Simple Queue using an Array

Simple (linear) queue · array implementation · its limitation

Simple (linear) queue

The simple queue is the plain FIFO list: insertion at the rear, deletion at the front, strict arrival-order service. It maps directly onto a one-dimensional array and its basic operations take constant time. It is the easiest queue to understand and implement, which makes it the reference point for the other queue types.

Array representation

A queue is stored in an array items[MAX] together with two integers. front is the index of the next element to delete; rear is the index of the last element inserted. Initialisation (deck 3, p.9) is front = 0; rear = -1;, which makes the queue empty because front > rear.

Conditions to quote in the exam Empty: front > rear (equivalently rear == front - 1). Full: rear == MAX - 1. Enqueue: ++rear, then store. Dequeue: read items[front], then front++. Number of elements: rear - front + 1.

Complete C program: operations

#define MAX 5 typedef int KeyType; typedef struct { KeyType items[MAX]; int front; /* index of the next element to delete */ int rear; /* index of the last element inserted */ } Queue; void initQueue(Queue *q) { q->front = 0; q->rear = -1; } /* empty */ int isEmpty(Queue *q) { return q->front > q->rear; } int isFull(Queue *q) { return q->rear == MAX - 1; } int enqueue(Queue *q, KeyType x) { /* Add(item) */ if (isFull(q)) return 0; /* overflow */ q->items[++q->rear] = x; /* advance rear, then store */ return 1; } int dequeue(Queue *q, KeyType *x) { /* Delete(item) */ if (isEmpty(q)) return 0; /* underflow */ *x = q->items[q->front++]; /* read, then advance front */ return 1; } int frontOf(Queue *q) { return q->items[q->front]; } /* peek: caller checks !isEmpty */ int rearOf(Queue *q) { return q->items[q->rear]; } void display(Queue *q) { for (int i = q->front; i <= q->rear; i++) printf("%d ", q->items[i]); printf("\n"); }

Enqueue and dequeue return a status instead of printing, so the caller decides what to do on overflow or underflow. The deck's pseudocode (Add(item), Delete(item)) maps one-to-one on these functions: check the condition, then rear++ / queue[rear] = item or item = queue[front] / front++.

Limitation of the linear queue

In a linear array queue, front and rear only ever move forward. Every dequeued cell is abandoned and never used again (a "virtual deletion"). Over time the free cells accumulate at the beginning of the array while rear reaches the last index, and the queue reports false overflow: it says it is full although it may hold few or even zero elements. In the extreme case, after MAX insertions the queue can never accept another element, no matter how many have been deleted.

The obvious remedy is to shift all remaining elements left after every dequeue so that front stays at index 0. That fixes the space problem but turns every dequeue into an O(n) operation. The measured cost of draining a queue of n elements this way (counted by the C program shift.c):

1.3

Circular Queue

Circular queue · both full-condition conventions

Idea

A circular queue treats the array as if its last position were connected back to its first. When rear reaches the last index, the next insertion goes to index 0 provided that cell is free. The wrap-around rule is

next = (current + 1) % MAX; /* rear = (rear + 1) % MAX; front = (front + 1) % MAX; */

The cells released by earlier dequeues are reused instead of being wasted, so the false overflow of section 1.2 disappears and no element is ever shifted. A circular queue is the natural choice for fixed-size buffers.

Enqueue and dequeue

Enqueue: (1) check whether the queue is full; (2) move rear to the next circular position; (3) store the item there. Dequeue: (1) check whether the queue is empty; (2) take the item at front; (3) move front to the next circular position, so the freed cell can be reused later.

The empty/full ambiguity and its two fixes

With only front and rear, an empty queue and a full queue can look identical: after the rear has chased the front all the way round, rear is one step behind front in both cases. The decks say "carefully define the empty and full conditions" and name two conventions (deck 3, p.13). Both are given in full below.

1.4

Queue using a Linked List

Implementation using linked lists

Linked-list representation

A linked queue stores each element in a dynamically allocated node. A node holds a data item and a link to the next node. Two pointers manage the queue: front points to the first node (the next to delete) and rear to the last node (where the next node is attached). An empty queue has front == rear == NULL. Unlike an array, the queue grows and shrinks one node at a time: overflow occurs only if memory allocation fails.

Fig 7. Linked queue holding 10, 20, 30. Each node has a data field and a link field. front points at the first node (the next to delete); rear points at the last node (where the next node is attached).
typedef struct node { KeyType data; struct node *link; } Node; typedef struct { Node *front; /* first node: deletion end */ Node *rear; /* last node: insertion end */ } LQueue; void initLQ(LQueue *q) { q->front = q->rear = NULL; } int lqEmpty(LQueue *q) { return q->front == NULL; } int lqEnqueue(LQueue *q, KeyType x) { Node *nw = (Node *)malloc(sizeof(Node)); if (nw == NULL) return 0; /* overflow = allocation failure */ nw->data = x; nw->link = NULL; /* new node is always the last */ if (q->rear == NULL) /* empty queue */ q->front = q->rear = nw; else { q->rear->link = nw; /* link after the old last node */ q->rear = nw; /* then move rear */ } return 1; } int lqDequeue(LQueue *q, KeyType *x) { if (q->front == NULL) return 0; /* underflow */ Node *temp = q->front; *x = temp->data; q->front = q->front->link; free(temp); if (q->front == NULL) /* the last node was removed */ q->rear = NULL; /* otherwise rear would dangle */ return 1; }

Why two pointers, and why the order of statements matters

Insertion happens at the tail and deletion at the head. If only front were kept, every enqueue would have to walk the whole list to find the last node (O(n)); the extra rear pointer makes it O(1). The new node's link is set to NULL before it is attached, and rear is moved after the old last node has been linked to it. In dequeue, the old front node is saved in temp before front moves, so it can be freed; and when the last node leaves, rear must also be reset to NULL, otherwise it would dangle on freed memory.

  • Enqueue into an empty queue: the new node becomes both front and rear.
  • Enqueue into a non-empty queue: rear->link = new; rear = new;
  • Dequeue from an empty queue: underflow.
  • Dequeue of the last node: front becomes NULL and rear must be set to NULL too.

2.1

Double-Ended Queue (Deque)

Double-ended queues and applications

Definition

A double-ended queue (deque, pronounced “deck”) is a linear list in which insertions and deletions may be made at either end. It generalises both the stack (use one end only) and the queue (insert at one end, delete at the other). There are two restricted forms:

  • Input-restricted deque — insertion is permitted at one end only; deletion is permitted at both ends.
  • Output-restricted deque — deletion is permitted at one end only; insertion is permitted at both ends.
Fig 9. Deque and its two restricted forms. Blue arrows are deletions (out), plum arrows are insertions (in).

Four operations define a deque: insertFront, insertRear, deleteFront, deleteRear, plus the usual isEmpty, isFull and peeks at either end.

Array implementation (circular)

A circular array suits a deque because positions can be reused at both ends. insertRear and deleteFront behave exactly as in the circular queue. The two new operations move the pointers in the opposite direction: insertFront first steps front backwards ((front - 1 + MAX) % MAX; the + MAX prevents a negative index in C) and then stores; deleteRear reads at rear and steps rear backwards. A count field distinguishes empty from full. Initially front = 0 and rear = MAX-1, i.e. rear sits one step behind front, so that the first insertRear goes to cell 0 and the first insertFront goes to cell MAX-1.

Priority Queue

Priority queues · array, list and heap implementations

Definition

In a priority queue the next element to be removed is chosen by priority rather than purely by arrival time. Priority can override arrival order. In this guide, as in the decks, a smaller number means higher priority; where two elements have equal priority, they are served in FIFO order (arrival order), which the decks call “tie handling”. Typical uses are CPU and job scheduling, event simulation and service systems where urgency matters.

Fig 11. Priority queue on the deck example (Job A p3, B p1, C p2, D p1). Arrival order is A, B, C, D; service order is B, D, C, A (programme output in this section).

The ADT is the queue ADT with a different delete rule: insert(item, priority) adds an element anywhere in the structure, and deleteHighest() removes and returns the element with the best priority. The implementation choice decides which of the two operations is cheap.

Implementation choices

  • Unordered array or list: insertion is trivial (append at the end); deletion must scan every element to find the highest priority.
  • Ordered array or list: elements are kept sorted by priority, so the best is at a known end and deletion is trivial; insertion must find the right place and shift elements.
  • Linked list: nodes can be kept sorted or unsorted; pointers replace contiguous storage but the same trade-off holds.
  • Binary heap: a specialised structure that makes both operations O(log n) (below).

Variant 1: unordered array

/* Variant 1: UNORDERED array. Insert O(1); delete must scan, O(n). */ typedef struct { Item a[MAX]; int n; } PQU; int puInsert(PQU *q, Item x) { if (q->n == MAX) return 0; q->a[q->n++] = x; /* just append at the rear */ return 1; } int puDelete(PQU *q, Item *out) { if (q->n == 0) return 0; int best = 0; for (int i = 1; i < q->n; i++) /* strict '<' keeps the EARLIEST of equals */ if (q->a[i].pri < q->a[best].pri) best = i; *out = q->a[best]; for (int i = best; i < q->n - 1; i++) /* close the gap, preserving order */ q->a[i] = q->a[i + 1]; q->n--; return 1; }

The strict < in the scan keeps the earliest of equal priorities, which gives FIFO tie-breaking; the shift afterwards preserves arrival order for the remaining elements. Insert is O(1); delete is O(n).

Variant 2: ordered array

/* Variant 2: ORDERED array. Highest priority kept at the END (index n-1), so delete is O(1); insert shifts to find its place, O(n). */ typedef struct { Item a[MAX]; int n; } PQO; int poInsert(PQO *q, Item x) { if (q->n == MAX) return 0; int i = q->n - 1; while (i >= 0 && q->a[i].pri <= x.pri) { /* '<=' puts the newcomer BEHIND equal-priority items */ q->a[i + 1] = q->a[i]; i--; } q->a[i + 1] = x; q->n++; return 1; } int poDelete(PQO *q, Item *out) { if (q->n == 0) return 0; *out = q->a[--q->n]; /* the last cell is the best item */ return 1; }

The array is sorted so that the best element is at the end, which makes deletion a single decrement of n. The <= in the insertion loop places a new element behind existing equal-priority elements, again preserving FIFO among ties. Insert is O(n); delete is O(1).

Variant 3: binary heap (summary)

A binary min-heap stores the elements in an array so that every parent has a priority no worse than its children; the root (index 0) is always the highest-priority element. For index i the parent is (i-1)/2 and the children are 2i+1, 2i+2. Insertion appends at the end and sifts up; deletion takes the root, moves the last element to the root and sifts down. Both walk one root-to-leaf path, so both are O(log n), and peeking the best is O(1). (Heaps are developed fully in the heaps unit; only the summary is needed here.)

Fig 12. Min-heap after inserting A3, B1, C2, D1 (array form below). Parent of index i is (i-1)/2, children are 2i+1 and 2i+2; the highest-priority job sits at index 0.
/* Variant 3: binary MIN-HEAP in an array (root = a[0]). Insert and delete O(log n). */ typedef struct { Item a[MAX]; int n; } PQH; int phInsert(PQH *q, Item x) { if (q->n == MAX) return 0; int i = q->n++; while (i > 0 && x.pri < q->a[(i - 1) / 2].pri) { /* sift up */ q->a[i] = q->a[(i - 1) / 2]; i = (i - 1) / 2; } q->a[i] = x; return 1; } int phDelete(PQH *q, Item *out) { if (q->n == 0) return 0; *out = q->a[0]; Item last = q->a[--q->n]; int i = 0; while (2 * i + 1 < q->n) { /* sift down */ int c = 2 * i + 1; if (c + 1 < q->n && q->a[c + 1].pri < q->a[c].pri) c++; if (last.pri <= q->a[c].pri) break; q->a[i] = q->a[c]; i = c; } if (q->n > 0) q->a[i] = last; return 1; }

Multiple Queues in a Single Array

Self-learning: implementing multiple queues in a single array

Not in your materials - added for syllabus completeness None of the three decks covers this topic; it appears only in the syllabus's self-learning list. The designs and code below are standard techniques written for this guide, and every trace is the output of the accompanying C programs.

Why share an array?

If a program needs several queues and each is given its own fixed array, a queue that fills up reports overflow even though the other queues have plenty of spare cells. Packing several queues into one array lets them share one block of storage and makes that block easier to size and allocate. The price is extra bookkeeping: every queue needs its own front and rear, and the queues must not overwrite each other.

Method 1: two queues, growing towards each other

Put Q1 at the left end growing rightwards and Q2 at the right end growing leftwards. Free space is shared in the middle, so either queue can use as much of it as it needs; overflow occurs only when the two rear pointers meet. Q1 occupies a[f1..r1] (empty when r1 == f1-1); Q2 occupies a[r2..f2] (empty when r2 == f2+1).

/* Two queues in ONE array: Q1 grows rightwards from index 0, Q2 grows LEFTwards from index N-1. They only collide in the middle. */ #define N 10 typedef struct { KeyType a[N]; int f1, r1; /* Q1 occupies a[f1 .. r1]; empty when r1 == f1-1 */ int f2, r2; /* Q2 occupies a[r2 .. f2]; empty when r2 == f2+1 */ } TwoQ; void initTwoQ(TwoQ *t) { t->f1 = 0; t->r1 = -1; t->f2 = N - 1; t->r2 = N; } int enq1(TwoQ *t, KeyType x) { if (t->r1 + 1 >= t->r2) return 0; /* next cell for Q1 is Q2's territory */ t->a[++t->r1] = x; return 1; } int enq2(TwoQ *t, KeyType x) { if (t->r2 - 1 <= t->r1) return 0; /* next cell for Q2 is Q1's territory */ t->a[--t->r2] = x; return 1; } int deq1(TwoQ *t, KeyType *x) { if (t->r1 < t->f1) return 0; *x = t->a[t->f1++]; return 1; } int deq2(TwoQ *t, KeyType *x) { if (t->r2 > t->f2) return 0; *x = t->a[t->f2--]; return 1; }

Method 2: k queues in k equal segments

For k queues, cut the array of N cells into k segments of N/k cells and manage each segment as its own circular queue (count convention). Queue i's local index p lives at physical cell i*SEG + p. Method 3 (mention): dynamic boundaries

To let a busy queue borrow space from an idle neighbour, keep a boundary array B[i] for the start of queue i. When queue i overflows, find the nearest queue j with spare room and shift the queues between them by one cell (or repack all queues in proportion to their recent growth — Garwick's algorithm). This reuses all the memory, at the cost of occasional O(n) data movement. Only the idea is expected in an exam; the two methods above are the ones to code.

Circular queue: efficiency analysis

  • Time: enqueue and dequeue each do a constant number of steps — one comparison, one modulo, one store or load, one counter update — so both are O(1) in the worst case, not just on average. Nothing is ever shifted.
  • The modulo cost: (i + 1) % MAX is a division. It can be replaced by i = (i + 1 == MAX) ? 0 : i + 1, or, if MAX is a power of two, by (i + 1) & (MAX - 1); this is a constant-factor saving only.
  • Space utilisation: the count variant uses all MAX cells (100%); the one-slot-empty variant uses MAX-1 (for MAX = 6 that is 83%, for MAX = 100 it is 99%). The count variant costs one integer; the other costs one cell.
  • Lifetime capacity: a linear queue of size MAX can accept only MAX insertions in total before the false overflow, whatever the deletions; a circular queue can process an unlimited number of items as long as no more than MAX (or MAX-1) are waiting at one time.
  • Display / traversal: O(n) for n stored items, using (front + i) % MAX rather than front..rear, which fails after wrap-around.

Scheduling: Round-Robin & Printer Jobs

Applications: scheduling · printer/job scheduling · round-robin

Why scheduling needs queues

Whenever jobs or requests arrive faster than a resource can serve them, they wait in a queue. A simple queue serves them in arrival order (FCFS); a priority queue serves the most urgent first; a circular queue gives each job a turn in rotation. The decks list CPU scheduling, print scheduling and general service requests as the standard scheduling applications.

CPU scheduling with a ready queue

The operating system keeps the processes that are ready to run in a ready queue. First-come-first-served simply runs each process to completion in queue order. Priority scheduling keeps the ready queue as a priority queue (section 2.2) so urgent processes run first. Round-robin (RR) is the time-sharing policy built directly on a FIFO queue, described next.

Round-robin scheduling with a queue

Each process may run for at most one time quantum q at a time. The scheduler repeatedly: (1) dequeues the process at the front of the ready queue; (2) runs it for min(q, remaining burst); (3) if it still has work left, enqueues it at the rear; otherwise it finishes. Because an unfinished process always goes to the back, every process gets a turn before any process gets a second one.

/* Round-robin: the ready queue holds process ids. Buffering: Ring Buffers

Applications: buffering · CPU task buffering

Buffering

A buffer is temporary storage that sits between a producer and a consumer working at different rates. A queue is the natural buffer because data must leave in the order it arrived. The decks give three examples: an I/O buffer between an input device and a processor, a network buffer holding packets before transmission or processing, and a circular buffer where a fixed-size storage area is reused continuously.

The ring buffer (circular buffer)

A ring buffer is a circular queue of fixed size used as a buffer. The producer writes at the tail; the consumer reads at the head; both wrap modulo the capacity. Because nothing is ever moved or allocated, put and get are O(1) and the memory use is constant, which is why ring buffers are used in device drivers, audio streaming, keyboard input and network cards.

/* Fixed-size ring buffer = circular queue with a count. The producer calls put(), the consumer calls get(). When full, put() refuses (or the producer waits); when empty, get() refuses (or the consumer waits). */ #define CAP 4 typedef struct { KeyType buf[CAP]; int head; /* next cell to read (front) */ int tail; /* next cell to write (one past rear) */ int count; } Ring; void ringInit(Ring *r) { r->head = r->tail = r->count = 0; } int put(Ring *r, KeyType x) { if (r->count == CAP) return 0; /* buffer full */ r->buf[r->tail] = x; r->tail = (r->tail + 1) % CAP; r->count++; return 1; } int get(Ring *r, KeyType *x) { if (r->count == 0) return 0; /* buffer empty */ *x = r->buf[r->head]; r->head = (r->head + 1) % CAP; r->count--; return 1; }

The code is the circular queue of section 1.3 (count convention) with the roles renamed: put is enqueue, get is dequeue, head is front and tail is the cell after the last item (the next write position).

Simulation: Bank Counter

Applications: simulation problems

Queues in simulation

A simulation imitates a real system on a computer so that its behaviour can be measured. Many systems are waiting lines: bank counters, toll booths, network routers, traffic lights. The decks list bank/service counters, traffic and network entities, and event lists as simulation uses of queues. Simulation questions usually ask: Who arrives? Who waits? Who is served next? What is the waiting time? The queue answers the first three directly; waiting time is computed from the start and arrival times.

Single-teller bank simulation

Customers arrive at known times and need a known service time. They join the rear of a FIFO queue; whenever the teller is free, the customer at the front is served. At each time tick the simulation (1) enqueues the customers who arrive now, (2) lets the finished customer leave, (3) if the teller is free, dequeues the next customer and records the start time. Waiting time = start time - arrival time.

/* One-teller bank: time-stepped simulation with a FIFO waiting line. */ typedef struct { int a[MAX]; int front, rear; } IQ; /* queue of customer indices */ void iqInit(IQ *q) { q->front = 0; q->rear = -1; } int iqEmpty(IQ *q){ return q->front > q->rear; } void iqPut(IQ *q, int v) { q->a[++q->rear] = v; } int iqGet(IQ *q) { return q->a[q->front++]; } void simulate(Cust c[], int n, int start[], int finish[]) { IQ line; iqInit(&line); int next = 0, busyUntil = 0, serving = -1, done = 0; for (int t = 0; done < n; t++) { while (next < n && c[next].arrive == t) iqPut(&line, next++); /* arrivals join the rear */ if (serving >= 0 && t == busyUntil) { finish[serving] = t; serving = -1; done++; } if (serving < 0 && !iqEmpty(&line)) { /* teller free: serve front */ serving = iqGet(&line); start[serving] = t; busyUntil = t + c[serving].service; } } }

Josephus Problem

Custom application: Josephus problem

Not in your materials - added for syllabus completeness The Josephus problem appears only in the syllabus's list of custom queue applications; none of the decks covers it. All outputs below come from the C program and are cross-checked against the standard recurrence.

The problem

n people stand in a circle numbered 1 to n. Starting at person 1, count k people (the k-th is the person at which you stop counting, counting the start person as 1); that person is eliminated, and counting restarts from the next person. Elimination continues until one person survives. The problem asks for the elimination order and the survivor.

Solution with a queue

A circular list is a queue whose front element is “the person where counting starts”. Moving the counter past a person is dequeue then enqueue at the rear (the person goes to the back of the circle). So, in each round: rotate k-1 times (dequeue + enqueue), then dequeue the k-th person permanently. When one person remains, that person is the survivor.

/* Josephus problem with a circular queue. People 1..n stand in a circle; every k-th person is eliminated until one survives. Each round: dequeue and re-enqueue (k-1) people, then dequeue the k-th for good. */ #define MAXN 100 typedef struct { int a[MAXN]; int front, rear, count; } CQ; void cqInit(CQ *q) { q->front = 0; q->rear = -1; q->count = 0; } void cqPut(CQ *q, int v) { q->rear = (q->rear + 1) % MAXN; q->a[q->rear] = v; q->count++; } int cqGet(CQ *q) { int v = q->a[q->front]; q->front = (q->front + 1) % MAXN; q->count--; return v; } int josephus(int n, int k, int order[]) { CQ q; cqInit(&q); for (int i = 1; i <= n; i++) cqPut(&q, i); int e = 0; while (q.count > 1) { for (int i = 1; i < k; i++) cqPut(&q, cqGet(&q)); /* skip k-1 people: move to the back */ order[e++] = cqGet(&q); /* k-th person is eliminated */ } return cqGet(&q); /* the survivor */ }

Combining stack and queue operations for complex problems

Not in your materials - added for syllabus completeness The syllabus lists “combining stack and queue operations for complex problems”; the decks contain no such material. The constructions below are the standard ones (and the Part A lab programs: stack using multiple queues, queue using multiple stacks). Every trace is program output.

A stack is LIFO and a queue is FIFO. Because each reverses the order of arrival in a different way, one structure can be built from the other, and the two together solve reversal and matching problems. In every trace below, stacks are written bottom to top and queues front to rear.

Queue using two stacks

Keep an inStack for enqueues and an outStack for dequeues. Enqueue just pushes onto inStack. Dequeue pops from outStack; only when outStack is empty are all elements popped from inStack and pushed onto outStack, which reverses them so that the oldest element ends on top. The transfer must be all-or-nothing and only when outStack is empty, otherwise the order would be corrupted.

/* QUEUE using two stacks: 'in' receives enqueues; 'out' serves dequeues. When 'out' is empty, pour ALL of 'in' into 'out' (this reverses the order). */ typedef struct { Stack in, out; } StackQueue; void sqInit(StackQueue *q) { sInit(&q->in); sInit(&q->out); } void sqEnqueue(StackQueue *q, int x) { push(&q->in, x); } /* O(1) */ int sqDequeue(StackQueue *q, int *x) { if (sEmpty(&q->out)) while (!sEmpty(&q->in)) push(&q->out, pop(&q->in)); /* transfer */ if (sEmpty(&q->out)) return 0; /* both empty: underflow */ *x = pop(&q->out); return 1; }

The same idea with two queues: put the new item into the empty queue q2, move everything from q1 behind it, then swap the names. q1 always has the newest item at its front.

Reversing a queue with a stack

Move the first k elements into a stack, pop them back into the queue (which reverses them and puts them at the rear), then rotate the remaining n-k elements to the rear to restore the original position. With k = n the whole queue is reversed.

/* Reverse the first k elements of a queue (k = n reverses the whole queue). */ void reverseFirstK(Q *q, int k) { Stack s; sInit(&s); int n = qsize(q); for (int i = 0; i < k; i++) push(&s, get(q)); /* k items into the stack */ while (!sEmpty(&s)) put(q, pop(&s)); /* popped reversed -> rear */ for (int i = 0; i < n - k; i++) put(q, get(q)); /* rotate the untouched n-k */ }

BFS in Graphs and Mazes

BFS in graphs using queue · maze problem

Breadth-first search (BFS)

Breadth-first search visits the vertices of a graph level by level: first the start vertex, then all its neighbours, then all vertices two edges away, and so on. A queue gives exactly this order: vertices are visited in the order they were discovered (FIFO), so all vertices at distance d are dequeued before any vertex at distance d+1. (Depth-first search uses a stack instead.) The decks list “Breadth-First Search: a queue supports level-by-level graph traversal” as an application; the algorithm itself is written out here.

  1. Mark the start vertex visited and enqueue it.
  2. While the queue is not empty: dequeue a vertex u and visit it.
  3. For every neighbour w of u not yet visited: mark it visited now, record its distance (dist[u]+1) and enqueue it.

Marking when a vertex is enqueued, not when it is dequeued, guarantees that each vertex enters the queue at most once.

#define V 7 /* vertices A..G = 0..6 */ int adj[V][V]; /* adjacency matrix */ void addEdge(int u, int v) { adj[u][v] = adj[v][u] = 1; } void bfs(int src) { int visited[V] = {0}, dist[V]; int queue[V], front = 0, rear = -1; /* each vertex enters the queue at most once */ for (int i = 0; i < V; i++) { dist[i] = -1; } visited[src] = 1; dist[src] = 0; queue[++rear] = src; /* enqueue the start vertex */ while (front <= rear) { /* while the queue is non-empty */ int u = queue[front++]; /* dequeue */ printf("%c ", 'A' + u); /* "visit" u */ for (int w = 0; w < V; w++) if (adj[u][w] && !visited[w]) { /* unvisited neighbour */ visited[w] = 1; /* mark when ENQUEUED */ dist[w] = dist[u] + 1; queue[++rear] = w; } } printf("\n"); }

Maze problem: shortest path in a grid

A maze on a grid is a graph whose vertices are the open cells and whose edges join cells that touch horizontally or vertically. The shortest way out is therefore a BFS from the start cell, remembering for each cell the cell it was reached from; the first time the exit is dequeued, its distance is minimal, and following the parents backwards gives the path. A stack (DFS) would find a path but not necessarily the shortest.

#define R 6 #define C 7 /* '#' wall, '.' open, 'S' start, 'E' exit */ char grid[R][C + 1] = { "S..#...", ".#.#.#.", ".#...#.", ".####.#", "......E", ".#####." }; typedef struct { int r, c; } Cell; int solveMaze(int sr, int sc, int er, int ec, Cell path[]) { int dist[R][C], pr[R][C], pc[R][C]; Cell queue[R * C]; int front = 0, rear = -1; int dr[4] = {-1, 1, 0, 0}, dc[4] = {0, 0, -1, 1}; /* up, down, left, right */ for (int i = 0; i < R; i++) for (int j = 0; j < C; j++) dist[i][j] = -1; dist[sr][sc] = 0; queue[++rear] = (Cell){sr, sc}; while (front <= rear) { Cell u = queue[front++]; if (u.r == er && u.c == ec) break; /* first arrival = shortest */ for (int d = 0; d < 4; d++) { int nr = u.r + dr[d], nc = u.c + dc[d]; if (nr < 0 || nr >= R || nc < 0 || nc >= C) continue; if (grid[nr][nc] == '#' || dist[nr][nc] != -1) continue; dist[nr][nc] = dist[u.r][u.c] + 1; pr[nr][nc] = u.r; pc[nr][nc] = u.c; /* remember where we came from */ queue[++rear] = (Cell){nr, nc}; } } if (dist[er][ec] == -1) return -1; /* no route */ int len = dist[er][ec]; int r = er, c = ec; for (int i = len; i >= 0; i--) { /* walk the parents backwards */ path[i] = (Cell){r, c}; int tr = pr[r][c], tc = pc[r][c]; r = tr; c = tc; } return len; }

Complexity one-liners

Circular array queue, linked queue (with rear), array deque, doubly linked deque: every operation O(1). Linear queue with shifting: dequeue O(n), n dequeues cost n(n-1)/2 moves. Priority queue: unordered O(1)/O(n); ordered O(n)/O(1); heap O(log n)/O(log n).

Frequently confused

  • False overflow (linear queue) vs genuine overflow (all cells occupied).
  • front as “first element” (count convention) vs “cell before the first element” (textbook convention).
  • Dequeue order in the textbook circular queue: advance front then read.
  • Heap does not preserve FIFO among equal priorities; ordered/unordered arrays do if coded with strict/non-strict comparisons as shown.
  • BFS uses a queue (level order); DFS uses a stack.
