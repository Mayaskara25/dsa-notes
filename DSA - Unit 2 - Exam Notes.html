1.1

Stack Fundamentals & Representation in C

Stack definitions & concepts · representing stacks in C

Definition

A Stack is a linear data structure that stores elements in a particular order in which operations are performed. Insertions and deletions happen only at one end, called the top. This gives the stack its defining behaviour: LIFO — Last In, First Out (equivalently FILO — First In, Last Out). The element inserted last is always the first one to be removed — exactly like a physical stack of plates: you can only add a plate to the top, and you can only remove the topmost plate.

Representing a Stack in C

The most common representation uses a fixed-size array along with an integer top that always points to the index of the most recently pushed element. An empty stack is represented by top = -1.

// Array-based stack representation #define SIZE 5 int stack[SIZE]; int top = -1; // -1 means empty
Fig 1. Array representation of a stack of size 5, holding {10, 20, 30} — top tracks the index of the most recently pushed element; indices above it are unused.

Key Terms

TermMeaning
TopPointer/index to the most recently inserted element — the only element directly accessible
OverflowAttempting to push onto a stack that is already full (top == SIZE-1)
UnderflowAttempting to pop from a stack that is already empty (top == -1)

1.2

Operations on a Stack

Push · Pop · Peek · isEmpty · isFull

Fig 2. LIFO behaviour — push always adds above the current top; pop always removes the current top. Nothing beneath the top can be touched directly.

Algorithms & C Implementation

Push (insert)

  1. If top == SIZE - 1, report overflow.
  2. Else, increment top and store the new element at stack[top].
void push(int s[], int *top) { if (*top == SIZE-1) { // overflow printf("Stack Overflow"); return; } scanf("%d", &s[++(*top)]); }

Pop (delete)

  1. If top == -1, report underflow.
  2. Else, read stack[top] and decrement top.
int pop(int *top) { if (*top == -1) // underflow return -1; return s[(*top)--]; }

Peek / Top

Returns the element at stack[top] without modifying top — errors if the stack is empty.

isEmpty & isFull

CheckCondition
isEmptytop == -1
isFulltop == SIZE - 1

Display

Print elements from stack[top] down to stack[0] so the top of the stack is shown first.

void display(int s[], int *top) { if (*top == -1) { printf("Stack is empty"); return; } for (int i = *top; i >= 0; i--) printf("%d ", s[i]); }

CIE-1 2024-25 · Quiz Q91 mark
Consider the following algorithm — declare a stack of characters; while there are more characters to read: read a character, push it on the stack; while the stack is not empty: pop a character off the stack, write it to the screen. What is the output for input "Bengaluru"?
Answer

Every character is pushed in order, then popped — and pop always returns the most-recently-pushed character first (LIFO), so the whole string comes back out reversed:

"Bengaluru" → "urulagneB"

This is a standard use of a stack: reversing a sequence, since LIFO order is the exact opposite of the input order.

1.3

Stack using a Linked List

Dynamic implementation · push = insert at front · pop = delete from front · array vs linked comparison

In the linked implementation, each stack element is a node {data, link} and top points to the first node. PUSH inserts a node at the beginning; POP removes the first node, so both are O(1) with no traversal. The stack grows until memory runs out, so there is no fixed capacity and no "stack full" check (only a failed malloc).

struct node { int data; struct node *link; } *top = NULL;

void push(int x) {
    struct node *p = (struct node*)malloc(sizeof(struct node));
    if (p == NULL) { printf("Overflow\n"); return; }
    p->data = x;
    p->link = top;       /* new node -> old top */
    top = p;             /* new node is the top */
}
int pop(void) {
    if (top == NULL) { printf("Underflow\n"); return -1; }
    struct node *t = top;
    int x = t->data;
    top = top->link;
    free(t);
    return x;
}

CIE-1 2024-25 · Quiz Q31 mark
The minimum number of stacks needed to implement a queue is: ____
Answer

2. One stack is used to accept incoming (enqueue) elements; when a dequeue is requested and the second (output) stack is empty, every element is popped from the input stack and pushed onto the output stack, reversing their order so the oldest element ends up on top — restoring FIFO behaviour from two LIFO stacks.

Infix, Postfix and Prefix Notation

NotationFormExample
Infix<operand> <operator> <operand>A + B
Postfix<operand> <operand> <operator>A B +
Prefix<operator> <operand> <operand>+ A B

Infix is natural for humans but ambiguous for a computer without extra rules for operator precedence, associativity, and parentheses. Postfix and prefix remove that ambiguity entirely: the position of each operator already fixes the order of evaluation, so no precedence table or parentheses are needed at evaluation time.

Algorithm: Infix → Postfix (using a stack)

  1. Scan the infix expression left to right.
  2. If the scanned character is an operand, append it to the output.
  3. If it is an operator:
    • If the stack is empty, or contains a '(', or the scanned operator has higher precedence than the stack's top operator — push it.
    • Otherwise, pop and output all operators from the stack with precedence ≥ the scanned operator, then push the scanned operator.
  4. If the scanned character is '(', push it.
  5. If it is ')', pop and output until a '(' is popped (discard both parentheses).
  6. Repeat steps 2–5 until input is exhausted.
  7. Pop and output any remaining operators from the stack.
Precedence used throughout this unit ^ (highest, right-associative) > *, / (left-associative) > +, - (lowest, left-associative). For equal precedence between two left-associative operators, the one already on the stack is popped first (left-to-right evaluation order).

Infix→Prefix Conversion

Applications of stack data structures · infix to prefix

Algorithm: Infix → Prefix (using a stack)

Prefix conversion reuses the postfix machinery with three extra steps:

  1. Reverse the infix expression.
  2. Swap every '(' with ')' and vice versa.
  3. Convert this reversed-and-swapped expression to postfix — but when comparing precedence for two operators of equal precedence, do not pop (only pop when the stack's top operator has strictly higher precedence). This preserves correct left-to-right evaluation order once the result is reversed back.
  4. Reverse the resulting postfix string — this is the prefix expression.
Why step 3's rule changes Reversing the scan direction effectively turns left-associative operators into right-associative ones for the purposes of the stack comparison. Popping on equal precedence (as in infix→postfix) would silently reorder same-precedence operators; skipping the pop preserves the original left-to-right grouping once everything is reversed back.

1.6

Postfix Expression Evaluation

Postfix expression evaluation and parsing

Algorithm

  1. Scan the postfix expression left to right.
  2. If the scanned token is an operand, push it onto the stack.
  3. If the scanned token is an operator, pop the top two elements (op2 then op1 — op2 comes off first since it was pushed last), apply the operator as op1 <operator> op2, and push the result back.
  4. After the scan, the single value left on the stack is the result.
Order matters for − and / Because the stack is LIFO, the element popped first is the right-hand operand. For 3 4 -: pop 4 (op2), pop 3 (op1), compute 3 − 4 = −1 — not 4 − 3.
float eval(char postfix[]) { float stack[20]; int top = -1; for (int i = 0; postfix[i] != '\0'; i++) { if (isdigit(postfix[i])) stack[++top] = postfix[i] - '0'; else { float op2 = stack[top--]; float op1 = stack[top--]; switch (postfix[i]) { case '+': stack[++top] = op1 + op2; break; case '-': stack[++top] = op1 - op2; break; case '*': stack[++top] = op1 * op2; break; case '/': stack[++top] = op1 / op2; break; } } } return stack[top]; }

1.7

Prefix Expression Evaluation

Lab · application of stack · evaluate a prefix (Polish) expression by scanning right to left

Idea

In a prefix expression the operator comes before its two operands (+ A B). Scanning from the left, an operator is met before the operands it needs, so a stack cannot evaluate it immediately. Scanning from the right reverses this: both operands of an operator have already been seen and are sitting on the stack when the operator arrives. So prefix evaluation is the postfix algorithm run backwards, with one change in operand order.

Algorithm

  1. Scan the prefix expression from right to left.
  2. If the token is an operand, push it.
  3. If the token is an operator, pop op1 (first pop — this is the left operand), then pop op2 (the right operand), compute op1 <operator> op2 and push the result.
  4. When the scan ends, the single value on the stack is the answer. Time O(n), stack depth at most the number of operands.
Postfix vs prefix — the one difference Postfix is scanned left to right and the first pop is the right operand (op2). Prefix is scanned right to left and the first pop is the left operand (op1). Getting this wrong flips − and /: for - 9 3 the 3 is pushed first, then 9, so the first pop gives 9 and the result is 9 − 3 = 6.
Lab program · verified by running in C6 marks
Write a C program to evaluate a prefix expression using a stack, and trace it for - + 7 * 4 5 + 2 0.
Answer — full program (single-digit operands; the trace is printed after every token)
#include <stdio.h>
#include <ctype.h>
#include <string.h>

int main(void) {
    char pre[] = "-+7*45+20";        /* (7 + 4*5) - (2 + 0) */
    int stack[20], top = -1;
    for (int i = strlen(pre) - 1; i >= 0; i--) {      /* scan RIGHT to LEFT */
        char ch = pre[i];
        if (isdigit((unsigned char)ch)) stack[++top] = ch - '0';
        else {
            int op1 = stack[top--];                    /* first pop = LEFT operand */
            int op2 = stack[top--];
            int r = 0;
            switch (ch) {
                case '+': r = op1 + op2; break;
                case '-': r = op1 - op2; break;
                case '*': r = op1 * op2; break;
                case '/': r = op1 / op2; break;
            }
            stack[++top] = r;
        }
        printf("%c  [", ch);
        for (int j = 0; j <= top; j++) printf("%s%d", j ? ", " : "", stack[j]);
        printf("]\n");
    }
    printf("Result = %d\n", stack[top]);
    return 0;
}

1.8

Parenthesis Balancing

Matching (, [, { using a stack · O(n) · syllabus application

An expression is balanced if every opening bracket has a matching closing bracket of the same type, and brackets close in the correct (nested) order. A stack fits because the most recent unmatched opening bracket must be the first to close.

  1. Scan left to right. Push every opening bracket ( [ {.
  2. On a closing bracket: if the stack is empty, it is unbalanced (extra closer). Otherwise pop and check that the popped bracket matches; if not, unbalanced.
  3. Ignore all other characters.
  4. After the scan, the expression is balanced only if the stack is empty (otherwise there are unmatched openers).
int balanced(char *e) {
    char st[100]; int top = -1;
    for (int i = 0; e[i]; i++) {
        char c = e[i];
        if (c=='(' || c=='[' || c=='{') st[++top] = c;
        else if (c==')' || c==']' || c=='}') {
            if (top == -1) return 0;                    /* extra closer */
            char o = st[top--];
            if ((c==')' && o!='(') || (c==']' && o!='[') || (c=='}' && o!='{'))
                return 0;                               /* wrong type   */
        }
    }
    return top == -1;                                   /* none left over */
}

Introduction to Recursion

Introduction to recursion

What is Recursion?

Recursion is a technique where a function solves a problem by calling itself on one or more smaller instances of the same problem. It is a natural approach for problems that can be broken down into smaller sub-problems that look identical in structure to the original.

Key Components of a Recursive Algorithm

  1. Decomposition — what is the smaller identical sub-problem? (e.g. for factorial(n), it's factorial(n−1)).
  2. Composition — how are the answers to the smaller sub-problem(s) combined to form the answer to the larger problem? (e.g. multiply the sub-result by n).
  3. Base case (stopping case) — the smallest problem that can be solved directly, without further decomposition. Every recursive method must have at least one.
Two rules a recursive function must always follow (1) It must call itself, on a strictly "smaller" version of the problem. (2) It must have a base case that does not make a further recursive call, and that is actually reachable from every valid input — otherwise the recursion never terminates (§2.3).

Recursion vs. Iteration

MechanismFunction calls itself with a smaller argumentLoop (for/while) repeats a block of code

EquivalenceEvery recursive algorithm can be rewritten iteratively (using an explicit stack for state), and vice versa.

Factorial function

Recursive Design

Factorial is the canonical first example of recursion, because its own mathematical definition is already recursive:

N! = (N-1)! * N for N > 1 1! = 1 base case
  • Decomposition: (N−1)!
  • Composition: multiply the sub-result by N
  • Base case: 1! = 1 (equivalently 0! = 1)
int factorial(int n) { int fact; if (n > 1) // recursive case (decomposition) fact = factorial(n - 1) * n; // composition else // base case fact = 1; return fact; }

2.3

Role of the Stack During Recursion Execution

Role of the stack during execution

The System Call Stack

Every recursive call is managed behind the scenes by an internal call stack maintained by the runtime system — not the array-based stack from Part 2, but the exact same LIFO principle:

  • When a method (recursive or not) begins execution, a new stack frame is pushed, holding that call's local variables, parameters, and the return address.
  • When a method ends (hits a return), its frame is popped, and control resumes in the caller's frame exactly where it left off.

This is precisely why the factorial(4) trace in Fig 3 grows downward (frames pushed: 4, 3, 2, 1) and then unwinds upward (frames popped in reverse: 1, 2, 3, 4) — the call stack enforces that the last call made (factorial(1)) is the first to return, which is exactly what makes composition happen in the correct order.

Stack Overflow from Infinite Recursion

Because each pending call keeps its frame on the stack until it returns, a recursive function that never reaches its base case keeps pushing frames indefinitely. Since the call stack has finite memory, this eventually exhausts it — a stack overflow error. This can happen because of:

  • No base case at all.
  • A base case that exists but is unreachable — e.g. bad decomposition that never actually shrinks the argument toward it.
  • The problem genuinely not getting smaller with each call.
Exam framing "Explain the role of the stack during execution" (of recursion, or of a specific recursive algorithm like binary search or Tower of Hanoi) is asking for exactly this: each recursive call pushes a new frame holding that call's parameters and local state; the base case is the only frame that returns without triggering a further push; frames then pop and their results combine (composition) in strict last-in-first-out order as the recursion unwinds.
CIE-1 2024-25 · Q2 (role-of-stack part)3 of 10 marks

Answer (binary search implementation in §2.4)

Each recursive call to binarySearch(arr, left, right, x) pushes a new stack frame holding that call's own left, right, and computed mid. The recursion halves the search range on every call (decomposition), so the maximum stack depth is only ⌈log₂ n⌉ + 1 frames for an array of size n — far shallower than, say, factorial's n frames. The base case (right < left, i.e. element not found, or arr[mid] == x, i.e. found) returns a value with no further call, and that value propagates back up through each waiting frame as the stack unwinds, becoming the final return value of the outermost call.

Recursive Binary Search

Binary search

Idea

Binary search finds the position of a target value in a sorted array by repeatedly comparing the target against the middle element and discarding the half of the array that cannot contain it. Each recursive call operates on a range half the size of the previous one — a textbook divide-and-conquer recursion.

  • Decomposition: search the left half or the right half of the current range.
  • Composition: none needed — the answer from the sub-call is the answer (this is a case of "tail recursion").
  • Base case: arr[mid] == x (found), or the range is empty, i.e. right < left (not found).
int binarySearch(int arr[], int left, int right, int x) { if (right >= left) { int mid = left + (right - left) / 2; if (arr[mid] == x) return mid; if (arr[mid] > x) return binarySearch(arr, left, mid - 1, x); return binarySearch(arr, mid + 1, right, x); } return -1; // not found }
Why left + (right-left)/2 instead of (left+right)/2 Both give the same mathematical result, but (left+right) can overflow a fixed-width integer for very large indices; left + (right-left)/2 avoids that. Either form is acceptable in an exam answer — mention the safer form if asked to "improve" the code.

2.5

Towers of Hanoi Problem

Towers of Hanoi problem

The Puzzle

Three pegs — Source (S), Temporary/spare (T), Destination (D) — hold n disks of decreasing diameter, all initially stacked on the source peg. The goal is to move the entire stack to the destination peg, moving one disk at a time, and never placing a larger disk on top of a smaller one.

Recursive Design

A tower of n disks can be moved from source to destination using the spare peg by:

  1. Decomposition: move the top n−1 disks from source to spare (using destination as the temporary peg for this sub-move).
  2. Composition: move the single remaining (largest) disk from source directly to destination.
  3. Move the n−1 disks from spare to destination (using source as the temporary peg).
  4. Base case: n == 0 — nothing to move.
void ToH(int n, char src, char dest, char temp) { if (n > 0) { ToH(n - 1, src, temp, dest); // decomposition printf("Move disk %d from %c to %c", n, src, dest); // composition ToH(n - 1, temp, dest, src); // decomposition } } // called as: ToH(n, 'A', 'C', 'B');
Fig 5. Towers of Hanoi — recursive decomposition. Moving n disks A→C reduces to: move n−1 disks A→B, move the largest disk A→C, move n−1 disks B→C.

Recurrence Relation & Minimum Moves

Let T(n) be the minimum number of moves to transfer n disks. Each call to move n disks makes two recursive calls to move n−1 disks, plus one direct move:

T(n) = 2·T(n-1) + 1, T(0) = 0 Solving: T(n) = 2n - 1

For n=3: T(3) = 2³−1 = 7 moves. For n=4: T(4) = 2⁴−1 = 15 moves. (Both confirmed by running the recursive algorithm and counting the printed moves.)

More Recursion Examples

Fibonacci Numbers

fibonacci(n) = fibonacci(n−1) + fibonacci(n−2), with base cases fibonacci(1)=0, fibonacci(2)=1 (this deck's indexing starts the sequence 0, 1, 1, 2, 3, 5, 8, 13, …).

int fibonacci(int n) { if (n == 1) return 0; if (n == 2) return 1; return fibonacci(n-1) + fibonacci(n-2); }

fibonacci(4) = 2 — verified: fib(3)=fib(2)+fib(1)=1+0=1, fib(4)=fib(3)+fib(2)=1+1=2.

GCD (Euclidean Algorithm)

GCD(m,n) = GCD(n, m mod n); base case GCD(m,0) = m.

int GCD(int m, int n) { if (n == 0) return m; return GCD(n, m % n); }

GCD(48, 18) = 6 — verified: GCD(48,18)→GCD(18,12)→GCD(12,6)→GCD(6,0)=6.

Sum of First N Natural Numbers

Sum(n) = Sum(n−1) + n; base case Sum(1) = 1.

int Sum(int n) { if (n == 1) return 1; return Sum(n - 1) + n; }

Sum(5) = 15 — verified: 1+2+3+4+5 = 15.

Number of Zeros in a Number

Decomposition: strip the last digit; if it's 0, add 1. Base case: a single-digit number.

int numberOfZeros(int n) { if (n == 0) return 1; if (n < 10) return 0; if (n % 10 == 0) return numberOfZeros(n / 10) + 1; return numberOfZeros(n / 10); }

numberOfZeros(2030) = 2 — verified: strips to 203 (last digit 3, no add) → 20 (last digit 0, +1) → 2 (single digit, 0). Total = 0+1+0 = 2.

3.1

Recursion, Backtracking & Undo/Redo with Stacks

Self-learning · removing recursion · backtracking (maze, N-Queens) · undo/redo · browser history

Using a stack to eliminate recursion

A recursive call is a frame pushed on the system call stack (parameters, locals, return address). To remove recursion, make the stack explicit: push the pending work onto your own stack and loop until the stack is empty. This avoids call-stack overflow on deep inputs. Typical pattern: replace f(n-1) by pushing the argument, popping it in a loop, and pushing new sub-problems.

Example — printing a list in reverse without recursion: push every element while traversing, then pop and print.

Backtracking

Backtracking builds a solution step by step and, when a step leads to a dead end, undoes it and tries the next choice. The stack holds the path of choices made so far; "backtrack" = pop.

  • Maze solving — push each cell as you move; at a dead end pop to the previous cell and try another direction; the stack contents at the exit are the path.
  • N-Queens — place one queen per row, pushing the column; if no safe column exists in a row, pop the previous row's queen and move it. For N = 4 there are exactly 2 solutions: queen columns (1,3,0,2) and (2,0,3,1), counted from 0 (verified).

Undo / Redo in a text editor

Use two stacks. Each edit is pushed on the undo stack. Undo pops the undo stack, reverses the edit and pushes it on the redo stack. Redo pops the redo stack, reapplies it and pushes it back on undo. Making a new edit clears the redo stack.

Browser history navigation

Two stacks again: back and forward. Visiting a page pushes the current page on back and clears forward. Back pops back and pushes the current page on forward; Forward does the reverse.

Custom Stack Variations

Self-learning · multiple stacks in one array · Min/Max stack · stack of plates

Multiple stacks in a single array

Two stacks can share one array of size N: stack A grows from index 0 upward (topA starts at −1) and stack B grows from index N−1 downward (topB starts at N). The array is full only when topA + 1 == topB, so neither stack overflows while there is free space overall. For more than two stacks, split the array into equal segments, or use the shifting method that moves neighbouring stacks when one overflows.

Min Stack (get minimum in O(1))

Keep an auxiliary stack that stores the minimum so far at each depth. On push, also push min(x, current min); on pop, pop both. Then getMin() is simply the top of the auxiliary stack. A Max stack is the same with max.

Classic Stack Problems

Self-learning · reverse a stack without extra space · Stock Span · Largest Rectangle in Histogram

Reverse a stack without extra space (using recursion)

No second stack or array is used; the recursion's own call stack holds the elements. reverse() pops the top, reverses the rest, then calls insertAtBottom() to place the popped element at the bottom. insertAtBottom(x) pops everything, pushes x, then pushes the elements back. Time O(n²), extra space only the call stack.

void insertAtBottom(int x) {
    if (isEmpty()) { push(x); return; }
    int t = pop();
    insertAtBottom(x);
    push(t);
}
void reverse(void) {
    if (isEmpty()) return;
    int t = pop();
    reverse();
    insertAtBottom(t);
}

Stack 1,2,3,4 (4 on top) becomes 4,3,2,1 (1 on top) — verified.

Stock Span problem

The span of a day's price is the number of consecutive previous days (including today) with price ≤ today's. Keep a stack of indices of days with decreasing prices: pop while the price at the top ≤ today's; span = today's index − index now on top (or index + 1 if empty); then push today. Each index is pushed and popped once, so O(n).

Iterative Tower of Hanoi using a Stack

Lab · application of stack · simulating the recursion with an explicit stack, and the classic parity method

Why make it iterative?

The recursive solution of §2.5 relies on the system call stack. Because every recursive call is just a frame on a stack (§2.3, §3.1), the same program can be written with a loop and a stack that we manage. This shows exactly what the machine does during recursion, and avoids stack overflow for deep recursion. Two iterative forms are standard.

Method 1: explicit stack of frames

Each frame holds (n, from, to, aux) and a flag saying whether it is a SOLVE request (move n disks) or a single MOVE of disk n. The recursive body solve(n−1, from, aux, to); move n; solve(n−1, aux, to, from) becomes: pop a frame; if it is a MOVE (or n = 1) print the move; otherwise push three frames in reverse order — the last step first — so that LIFO order replays them as first step, move, last step.

  1. Push SOLVE(n, A, C, B).
  2. While the stack is not empty, pop a frame f.
  3. If f is a MOVE or f.n == 1, print "Move disk f.n from f.from to f.to".
  4. Else push SOLVE(n−1, aux, to, from), then MOVE(n, from, to), then SOLVE(n−1, from, aux, to).
Fig 6. Explicit-stack Tower of Hanoi for n = 3 (A to C via B): the frame SOLVE(3) is replaced by three frames, pushed last-step-first.

Frame trace for n = 2 (A to C via B): pop SOLVE(2) → push SOLVE(1, B→C), MOVE(2, A→C), SOLVE(1, A→B). Pops then print: disk 1 A→B, disk 2 A→C, disk 1 B→C (3 moves, checked in C).

Method 2: the parity (odd/even) rule

With pegs A, B, C and n disks (A the source, C the target), repeat for 2ⁿ − 1 moves:

  • Odd-numbered moves (1st, 3rd, …) move the smallest disk one peg along a fixed cycle: if n is odd, A → C → B → A …; if n is even, A → B → C → A ….
  • Even-numbered moves make the only legal move between the other two pegs (the smaller top disk moves onto the larger; if one peg is empty, a disk moves onto it).

The program below keeps each peg as an array stack (§1.1) so "legal move" is just comparing two tops.

#include <stdlib.h>

/* ---------- recursive reference ---------- */
void rec(int n, char a, char b, char c) {   /* move n disks a -> c using b */
    if (n == 0) return;
    rec(n-1, a, c, b);
    printf("Move disk %d from %c to %c\n", n, a, c);
    rec(n-1, b, a, c);
}

/* ---------- method 1: explicit stack of frames ---------- */
typedef struct { int n; char from, to, aux; int moveOnly; } FRAME;

void hanoi_stack(int n) {
    FRAME st[100]; int top = -1;
    st[++top] = (FRAME){n, 'A', 'C', 'B', 0};
    while (top >= 0) {
        FRAME f = st[top--];
        if (f.moveOnly || f.n == 1) {
            printf("Move disk %d from %c to %c\n", f.n, f.from, f.to);
            continue;
        }
        /* push in REVERSE order of execution (LIFO) */
        st[++top] = (FRAME){f.n-1, f.aux,  f.to,  f.from, 0};   /* 3rd: n-1 aux -> to   */
        st[++top] = (FRAME){f.n,   f.from, f.to,  f.aux,  1};   /* 2nd: move disk n     */
        st[++top] = (FRAME){f.n-1, f.from, f.aux, f.to,   0};   /* 1st: n-1 from -> aux */
    }
}

/* ---------- method 2: parity rule with three array stacks ---------- */
int peg[3][20], tp[3];
const char name[3] = {'A','B','C'};
void mv(int s, int d) {
    int disk = peg[s][--tp[s]];
    peg[d][tp[d]++] = disk;
    printf("Move disk %d from %c to %c\n", disk, name[s], name[d]);
}
void legal(int x, int y) {                   /* the only legal move between pegs x and y */
    if (tp[x] == 0) mv(y, x);
    else if (tp[y] == 0) mv(x, y);
    else if (peg[x][tp[x]-1] < peg[y][tp[y]-1]) mv(x, y);
    else mv(y, x);
}
void hanoi_parity(int n) {
    for (int i = n; i >= 1; i--) peg[0][tp[0]++] = i;
    int small = 0;                            /* peg holding disk 1 */
    int dir = (n % 2) ? 2 : 1;                /* odd: A->C->B->A ; even: A->B->C->A */
    long total = (1L << n) - 1;
    for (long m = 1; m <= total; m++) {
        if (m % 2 == 1) { int nx = (small + dir) % 3; mv(small, nx); small = nx; }
        else { int x = (small + 1) % 3, y = (small + 2) % 3; legal(x, y); }
    }
}

int main(int argc, char **argv) {
    int n = argc > 1 ? atoi(argv[1]) : 3;
    int which = argc > 2 ? atoi(argv[2]) : 0;
    if (which == 0) rec(n, 'A', 'B', 'C');
    else if (which == 1) hanoi_stack(n);
    else hanoi_parity(n);
    return 0;
}

Quick Revision

One-page cheat sheet — Unit II: stacks and applications

Stack

  • LIFO. top = -1 empty; top == MAX-1 full. Push: check overflow → stack[++top] = x. Pop: check underflow → stack[top--]. Peek: read stack[top]. All O(1).
  • Linked stack: push = insert at front, pop = delete from front; no fixed capacity.
  • Precedence: ^ > * / > + -; ^ is right-associative.

Expressions

Infix → Postfix: operand→output; ( → push; ) → pop till (; operator → pop ≥ precedence, then push Infix → Prefix: reverse, swap ( ), convert with "pop only if STRICTLY greater", reverse result Postfix eval: operand→push; operator→ pop op2, pop op1, push (op1 OP op2) Prefix eval: scan RIGHT→LEFT; operand→push; operator→ pop op1 (left), pop op2, push (op1 OP op2)

Parentheses

Push openers; on a closer pop and match; at the end the stack must be empty. O(n).

Recursion & Tower of Hanoi

  • Base case + recursive case; each call pushes a frame on the call stack.
  • Hanoi: T(n) = 2T(n-1) + 1 = 2ⁿ − 1 (n=3 → 7, n=4 → 15).
  • Iterative Hanoi: explicit stack — push SOLVE(n−1, aux→to), MOVE n, SOLVE(n−1, from→aux) (reverse order). Parity method: odd moves shift disk 1 (n odd: A→C→B; n even: A→B→C), even moves = the only legal move among the other two pegs. n=3: 1:A→C, 2:A→B, 1:C→B, 3:A→C, 1:B→A, 2:B→C, 1:A→C.

Self-learning one-liners

  • Reverse a stack: pop top, reverse rest, insert at bottom. Min stack: parallel stack of minimums.
  • Two stacks in one array: A from the left, B from the right; full when topA + 1 == topB.
  • Undo/redo: two stacks; new edit clears redo. Backtracking: pop = undo the last choice.
  • Stock span: stack of indices, pop while price ≤ today. Histogram: stack of increasing heights, area on pop.
