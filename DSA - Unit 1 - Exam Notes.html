1.1

Data Structures: Concepts & Types

Introduction to data structures · types of data structures · linear & non-linear data structures

Not in your materials — added for syllabus completeness Neither source deck opens with this topic — both jump straight into stacks. This section is written from standard curriculum material so the guide is self-sufficient, and it directly answers SEE Q1.3 ("List the differences between Linear and Non-Linear data structures").

What is a Data Structure?

A data structure is a specific way of organising, storing, and managing data in memory so that it can be accessed and modified efficiently. The choice of data structure determines how efficiently operations such as insertion, deletion, searching, and traversal can be performed on the data. The same collection of values can be organised as an array, a linked list, a tree, or a graph — each choice trades off memory usage, access speed, and the cost of insertion/deletion differently.

Types of Data Structures

Data structures are broadly classified into two categories based on how their elements are arranged relative to one another: linear and non-linear.

Fig 1. Classification of data structures — linear structures arrange elements in a single sequence; non-linear structures let elements connect in branching or interconnected ways.

Linear Data Structures

In a linear data structure, elements are arranged in a sequential order, one after another, so that each element (except the first and last) has exactly one predecessor and one successor. Traversal happens in a single run — front to back. Examples: Array, Stack, Queue, Linked List.

Non-Linear Data Structures

In a non-linear data structure, elements are not arranged sequentially — an element may connect to multiple other elements, so traversal can branch. This models hierarchical or networked relationships that a straight sequence cannot capture. Examples: Tree (hierarchical, parent-child relationships), Graph (arbitrary interconnections between nodes).

Memory utilisationOften less efficient for sparse/hierarchical relationshipsGenerally more memory-efficient for such relationships

1.2

Data, Data Types, ADT & Operations

Data vs information · primitive vs non-primitive · static vs dynamic · abstract data type · operations on data structures · applications

Data and Information

Data is the basic entity or fact used in a calculation or manipulation — raw values without context (numerical or alphanumerical). Information is data given context and meaning. The number 35 is data; "the temperature today is 35 °C" is information. A data structure organises data so it can be turned into information efficiently.

Data Type vs Data Structure

A data type says what kind of values a variable can hold (int, float, char) and which operations are legal on them. A data structure is the logical relationship between individual data elements together with the operations to organise, access and process them in memory.

Primitive vs Non-Primitive Data Structures

Non-primitive structures split into linear and non-linear (see §1.1). Linear structures are either sequential (array-based: array, stack, queue — consecutive memory) or linked (nodes joined by pointers: linked list, linked stack, linked queue).

Static vs Dynamic Data Structures

StaticDynamic

Abstract Data Type (ADT)

An Abstract Data Type is a conceptual model of a data structure: it specifies the data objects, the relationships among them and the operations allowed, but says what each operation does, not how it is implemented. The user depends only on the operations, so the implementation can change (a stack ADT can be built on an array or on a linked list) without changing client code. This is data abstraction.

// Stack ADT — specification only Data: an ordered collection with one open end (TOP) Operations: push(x), pop(), peek(), isEmpty(), isFull() Rule: last element pushed is the first popped (LIFO)

Operations on Non-Primitive Data Structures

  • Creating — setting up the structure in memory.
  • Inserting — adding an element at a position.
  • Deleting — removing an element.
  • Searching — finding the location of an element.
  • Sorting — arranging elements in a specified order.
  • Merging — combining two lists into one.
  • Traversing — visiting every element once, e.g. to display or process it.

Applications of Data Structures

Compiler design (symbol tables, parsing), operating systems (process queues, memory management), database management systems (indexes), numerical analysis, graphics, artificial intelligence, simulation, and statistical packages.

Exam tip "Primitive vs non-primitive" and "linear vs non-linear" are the standard 2-mark theory questions. Always give one example each and say whether the structure is static (array) or dynamic (linked list).

2.1

Static vs Dynamic Memory Allocation

Memory allocation · compile-time vs run-time · stack/data area vs heap · why linked lists need dynamic allocation

Memory allocation is the process of reserving a part of computer memory for a program's data. There are two kinds.

Static Memory Allocation

Memory is allocated at compile time. Once allocated, it can be neither extended nor reduced while the program runs. It lives in the stack or data area. It is fast and simple (the compiler frees it), but if too much is reserved it is wasted, and if too little is reserved the program overflows. Use it only when the data size is known in advance, e.g. int a[100];.

Dynamic Memory Allocation

Memory is allocated at run time from the heap using library functions, in exactly the amount needed. It can be released when no longer required, so utilisation is efficient and the size need not be known in advance. The costs: the programmer must manage pointers, allocation is slower, and memory that is not freed leaks.

Done at compile timeDone at run time

Link to linked lists A linked list allocates each node separately with malloc when needed, which is why it can grow and shrink at run time. The functions are covered next in §2.2.

2.2

malloc, calloc, free, realloc

Dynamic Memory Allocation

Not in your materials — added for syllabus completeness Neither source deck explains these four functions — both only ever call malloc/free inline, without teaching syntax, return values, or failure modes. This section is written from standard C reference material so the guide is self-sufficient, and directly answers three exam questions below.

Why Dynamic Memory Allocation?

An array's size is fixed at compile time — declaring int arr[100] commits to exactly 100 elements whether the program ends up needing 3 or 3000. Dynamic memory allocation requests memory from the heap at run time, in the exact amount needed, and is what makes data structures like linked lists, stacks, and queues able to grow node by node instead of being capped by a fixed array size (this is also the direct answer to "differentiate arrays and dynamic memory allocation" below).

The Four Functions

FunctionSyntaxBehaviour
mallocvoid* malloc(size_t size)Allocates size bytes of uninitialised memory; returns a pointer to it, or NULL on failure.
callocvoid* calloc(size_t n, size_t size)Allocates memory for n elements of size bytes each, and zero-initialises the whole block; returns a pointer, or NULL on failure.
freevoid free(void* ptr)Releases a block previously returned by malloc/calloc/realloc back to the heap. Freeing an already-freed or non-heap pointer is undefined behaviour.
reallocvoid* realloc(void* ptr, size_t newsize)Resizes a previously allocated block to newsize bytes, preserving existing contents up to the smaller of the old/new sizes; may move the block, so the caller must use the returned pointer, not the original.
// malloc: uninitialised int *p = (int*) malloc(5 * sizeof(int)); // 5 ints, garbage values // calloc: zero-initialised int *q = (int*) calloc(5, sizeof(int)); // 5 ints, all set to 0 // realloc: grow/shrink an existing block q = (int*) realloc(q, 10 * sizeof(int)); // now 10 ints; first 5 preserved // free: release it free(p); free(q);
Common failure modes to name in an exam answer NULL return — always check before dereferencing; the heap can be exhausted. Memory leak — losing the only pointer to a block (e.g. reassigning the pointer variable) before calling free means that memory can never be reclaimed for the rest of the program's run. Dangling pointer — using a pointer after its block has been freed is undefined behaviour, since the memory may already have been reused for something else.
CIE 21-22 Test-I · Q2b & CIE-II 2024-25 · Q1b3 marks / 4 marks
Explain with syntax any two dynamic memory allocation functions. / Differentiate between arrays and dynamic memory allocation.
Answer

Pick any two rows from the table above and state syntax + behaviour (e.g. malloc vs calloc, contrasting "uninitialised" vs "zero-initialised" — that contrast is usually the mark). For the arrays comparison: arrays are fixed-size, allocated at compile time (usually on the stack), with no manual release needed; dynamically allocated memory is variable-size, requested at run time from the heap, and must be explicitly released with free or it leaks for the remainder of the program.

SEE Jan/Feb 2025 · Q1.92 marks
Predict the output of the following C code:
char *p = calloc(100,1); p = "welcome"; printf("%s\n", p);
Answer

Output: welcome. The teaching point is what doesn't happen: p = "welcome" does not copy the string into the 100-byte calloc'd block — it rebinds the pointer variable p to point at the string literal "welcome" instead. The original 100-byte block is now unreachable (no pointer references it anymore) and can never be freed — a classic memory leak triggered by pointer reassignment instead of content copy (which would have needed strcpy(p, "welcome")).

3.1

Definition, Terminology & Types of Linked Lists

Definition and terminology · Singly Linked List (SLL)

Definition

A linked list is a linear data structure in which elements (nodes) are not stored contiguously in memory. Instead, each node holds its data plus one or more pointers ("links") to other nodes, and the structure is traversed by following those links. This trades away the constant-time random access an array gives you, in exchange for cheap insertion/deletion anywhere in the list without shifting elements — and for growing one node at a time via dynamic memory allocation (§2.2) instead of needing a fixed size up front.

Node Structure & Terminology

struct node { int info; // the data field struct node *link; // pointer to the next node }; typedef struct node *NODE;
TermMeaning
NodeOne unit of the list: a data field (info) plus a link field (link)
first / headExternal pointer to the first node of the list
NULL linkMarks the end of the list — the last node's link is NULL
TraversalVisiting every node by repeatedly following link from first until NULL
Fig 2. A 3-node SLL holding 10→20→30. Each cell is one node: left half is info, right half is link; the last node's link is NULL.

Types of Linked Lists

Four variants exist, differing only in how the link field(s) are wired:

TypeStructure
Singly Linked List (SLL)One link per node, pointing forward only; last node's link is NULL. The base case for every later operation.
Circular Singly Linked List (CSLL)Same as SLL, but the last node's link points back to the first node instead of NULL — no NULL anywhere in a non-empty list.
Doubly Linked List (DLL)Two links per node — one forward, one backward — enabling traversal in either direction.
Circular Doubly Linked List (CDLL)DLL with the forward link of the last node pointing to the first, and the backward link of the first pointing to the last.
Scope note SLL operations are covered in §3.2–§3.4 and worked in §3.9. The circular, doubly and circular doubly lists have their own sections (§3.8–§3.7); polynomial arithmetic and other applications are in Part 4.

3.2

SLL: Insertion (Front & Rear)

Operations on SLL: insertion

Insert at Front

The new node becomes the first node: point its link at the old first, then update first to the new node. This is an O(1) operation — no traversal needed.

NODE insertfront(NODE first, int item) { NODE temp = (NODE) malloc(sizeof(struct node)); temp->info = item; temp->link = first; return temp; // temp is the new first }

Insert at Rear

Traverse to the last node (the one whose link is NULL), then attach the new node there. This needs O(n) time since the whole list must be walked to find the end — unless a separate "last" pointer is maintained.

NODE insertrear(NODE first, int item) { NODE temp = (NODE) malloc(sizeof(struct node)); temp->info = item; temp->link = NULL; if (first == NULL) return temp; NODE cur = first; while (cur->link != NULL) cur = cur->link; cur->link = temp; return first; }
Fig 3. Insert-front rewires one link and moves first; insert-rear walks to the current last node before rewiring its (previously NULL) link.

3.3

SLL: Deletion & Ordered Insert

Operations on SLL: deletion and display

Delete by Key (Value)

Two cases: the node to delete is the first node (update first directly), or it's somewhere further in — in which case a trailing pointer is needed, since an SLL node has no way to reach its predecessor.

NODE deleteinfo(NODE first, int key) { NODE temp, cur, prev; if (key == first->info) { temp = first; first = first->link; printf("\nele del is %d", temp->info); free(temp); return first; } prev = NULL; cur = first; while (cur != NULL && key != cur->info) { prev = cur; cur = cur->link; } if (cur == NULL) { printf("\n%d has not been there", key); return first; } prev->link = cur->link; printf("\n%d is deleted", cur->info); free(cur); return first; }

Delete by Position

Same pattern, but the loop counts positions instead of comparing values.

NODE deletepos(NODE first, int pos) { NODE cur, prev; int ct = 1; if (first == NULL) { printf("empty"); return first; } if (pos == 1) { NODE temp = first; first = first->link; printf("\n%d is deleted", temp->info); free(temp); return first; } cur = first; while (cur != NULL && ct != pos) { prev = cur; cur = cur->link; ct++; } if (ct != pos) { printf("invalid position"); return first; } prev->link = cur->link; printf("\n%d is deleted", cur->info); free(cur); return first; }
Fig 4. Deleting the 2nd node: prev's link is redirected past cur to cur's successor before cur is freed — the same rewiring pattern used by delete-by-key.

Insert into an Ordered List

If the list is kept sorted (Ni ≤ Ni+1 for all i), a new item is inserted just before the first node whose value exceeds it — keeping the list sorted without a separate sort pass.

NODE insertorder(NODE first, int item) { NODE temp = (NODE) malloc(sizeof(struct node)); temp->info = item; temp->link = NULL; if (first == NULL) return temp; if (item <= first->info) { temp->link = first; return temp; } NODE cur = first, prev; while (cur != NULL && item > cur->info) { prev = cur; cur = cur->link; } prev->link = temp; temp->link = cur; return first; }
CIE 21-22 Test-I · Q2a7 marks
Develop C functions to perform the following operations on a singly linked list: (1) Replacing all nodes which have the data 'x' by 'y'. (2) Create an ordered list (a list of n nodes such that Ni ≤ Ni+1 for all 1 ≤ i ≤ n-1).
Answer

Lab program (Part A) · verified4 marks
Write a function to search for an element in a singly linked list and report its position.
Answer — plain linear search (O(n))
/* returns 1-based position of key, or 0 if absent */
int search(struct node *head, int key) {
    int pos = 1;
    for (struct node *p = head; p != NULL; p = p->link, pos++)
        if (p->data == key) return pos;
    return 0;
}

On the list 10→20→30→40, search(head, 30) returns 3 and search(head, 99) returns 0 (checked in C). A linked list offers no random access, so even a sorted list needs this node-by-node walk.

3.4

getnode, freenode & Header Node

getnode, freenode, and header node

Not in your materials — added for syllabus completeness Neither source deck names getnode/freenode as separate functions — every insert/delete function in both decks calls malloc/free directly inline (see §3.2–§3.3). The two functions below are the standard wrappers the syllabus names; wherever the decks write malloc(sizeof(struct node)) or free(temp) inline, substituting a call to getnode() / freenode() is functionally identical.

getnode & freenode

Wrapping allocation/deallocation in named functions keeps every insert operation from repeating the same malloc boilerplate, and gives one place to add error-checking (e.g. a NULL check) for the whole program.

NODE getnode() { NODE temp = (NODE) malloc(sizeof(struct node)); if (temp == NULL) { printf("Out of memory"); exit(0); } return temp; } void freenode(NODE p) { free(p); }

With these, insertfront from §3.2 simplifies to:

NODE insertfront(NODE first, int item) { NODE temp = getnode(); temp->info = item; temp->link = first; return temp; }

Header Node

A header node is a special extra node kept at the front of the list, holding metadata about the list itself — commonly a node count or a description of the list's purpose — rather than an actual data element. Its link field still points to the first real node.

Fig 5. A headed SLL: the header node (here storing a node count) sits before the first real node; the external pointer header never changes even as the list grows or shrinks.
Why bother with a header node Without one, inserting or deleting the very first real node is a special case (it changes what the external first pointer refers to). With a header node, the external pointer always refers to the header, which never moves — every real insertion/deletion becomes a "modify some node's link" operation, with no special-casing for "am I at the front?" A header list is empty when header->link == NULL.

3.5

Circular Linked Lists

Last node points back to the first · header node / last pointer · insertion, deletion, traversal

Not in your earlier materials — written from the new Unit I deck The deck's circular-list algorithm slides are images; the algorithms below are the standard ones, written out in full and tested in C.

Definition

A circular linked list is a singly linked list in which the link of the last node points to the first node instead of NULL. It therefore has neither a beginning nor an end: starting from any node, you can reach every other node. Because there is no NULL to stop at, traversal ends when the pointer returns to the starting node.

Two ways are used to know where the list starts:

  • an external pointer (first, or better last) to a node of the list; or
  • a header node as the first node, marked by a sentinel value or a flag. The last node points to the header.
Fig 6. A circular singly linked list of three nodes — no NULL anywhere.

Why use an external pointer to the last node?

If last points to the last node, then last->link is the first node. So both ends are reachable in O(1): insertion at the front, insertion at the rear and deletion from the front all take constant time. With only a first pointer, inserting at the rear costs O(n) because you must walk around the whole list.

typedef struct node { int data; struct node *link; } NODE;

/* insert at front — last is the external pointer */
NODE* insert_front(NODE *last, int x) {
    NODE *p = (NODE*)malloc(sizeof(NODE));
    p->data = x;
    if (last == NULL) { p->link = p; return p; }   /* first node points to itself */
    p->link = last->link;       /* new node -> old first */
    last->link = p;             /* last -> new first   */
    return last;
}

/* insert at rear: same rewiring, then move last */
NODE* insert_rear(NODE *last, int x) {
    last = insert_front(last, x);
    return last->link;           /* new node becomes last */
}

/* delete from front */
NODE* delete_front(NODE *last) {
    if (last == NULL) { printf("List empty\n"); return NULL; }
    NODE *first = last->link;
    if (first == last) { free(first); return NULL; }  /* only one node */
    last->link = first->link;
    free(first);
    return last;
}

/* display */
void display(NODE *last) {
    if (last == NULL) return;
    NODE *t = last->link;
    do { printf("%d ", t->data); t = t->link; } while (t != last->link);
}
Common mistake Traversal must use do … while (or stop when you return to the start), never while (p != NULL) — that loops forever on a circular list. Handle the empty list and the single-node list as separate cases in every delete.

Deletion from the end

With a single last pointer, deleting the last node needs the previous node, so you must walk from last->link until p->link == last: O(n). Set p->link = last->link, free last, and make p the new last.

3.6

Doubly Linked Lists

Node with llink, data, rlink · insertion and deletion · SLL vs DLL · browser-history scenario

Definition and Node Structure

A doubly linked list is a collection of nodes, each with three parts: llink (address of the previous node), data, and rlink (address of the next node). The first node's llink and the last node's rlink are NULL. Because every node knows both neighbours, the list can be traversed in either direction.

struct node {
    int data;
    struct node *rlink;   /* next     */
    struct node *llink;   /* previous */
};
Fig 7. A doubly linked list: each node has llink | data | rlink.

Insertion at the Front

NODE* insert_front(NODE *head, int x) {
    NODE *p = (NODE*)malloc(sizeof(NODE));
    p->data = x;
    p->llink = NULL;
    p->rlink = head;
    if (head != NULL) head->llink = p;
    return p;                       /* new head */
}

Insertion at the Rear

NODE* insert_rear(NODE *head, int x) {
    NODE *p = (NODE*)malloc(sizeof(NODE));
    p->data = x; p->rlink = NULL;
    if (head == NULL) { p->llink = NULL; return p; }
    NODE *t = head;
    while (t->rlink != NULL) t = t->rlink;
    t->rlink = p;                   /* old last -> new */
    p->llink = t;                   /* new -> old last */
    return head;
}

Insertion after a Given Node

To insert p after node q: four pointers change, and the order matters because you must not lose q->rlink.

p->rlink = q->rlink;
p->llink = q;
if (q->rlink != NULL) q->rlink->llink = p;
q->rlink = p;

Deletion

Deleting a node needs only the pointer to the node itself, because it already holds its predecessor — no trailing pointer is required, unlike an SLL.

NODE* delete_node(NODE *head, NODE *d) {      /* d points to node to delete */
    if (head == NULL || d == NULL) return head;
    if (d->llink != NULL) d->llink->rlink = d->rlink;
    else                  head = d->rlink;    /* deleting the first node */
    if (d->rlink != NULL) d->rlink->llink = d->llink;
    free(d);
    return head;
}

Circular Doubly Linked Lists

Doubly linked + circular · deletion from beginning, end and a given position

Definition

A circular doubly linked list (CDLL) combines the two ideas: every node has prev and next pointers, the last node's next points to the head, and the head's prev points to the last node. Nothing is NULL. The key benefit is that the last node is reachable in O(1) as head->prev, so both end operations are constant time without an extra pointer.

Fig 8. Circular doubly linked list: grey = next pointers, purple = prev pointers.

Delete from the Beginning

  1. If head == NULL: print "List empty, deletion not possible" and return.
  2. If head->next == head (one node): free it, set head = NULL, return.
  3. Otherwise: temp = head; last = head->prev; head = head->next; head->prev = last; last->next = head; free(temp); return head.

Delete from the End

  1. Empty list: report and return.
  2. One node (head->next == head): free it, set head = NULL.
  3. Otherwise: last = head->prev; second_last = last->prev; second_last->next = head; head->prev = second_last; free(last); return head.

Delete at a Given Position

NODE* delete_pos(NODE *head, int pos) {
    if (head == NULL) { printf("List empty\n"); return head; }
    if (pos == 1)  return delete_begin(head);
    NODE *t = head; int count = 1;
    while (count < pos) {
        t = t->next; count++;
        if (t == head) { printf("Invalid position\n"); return head; }
    }
    t->prev->next = t->next;
    t->next->prev = t->prev;
    free(t);
    return head;
}
Common mistake Forgetting the one-node case: there head->next == head and head->prev == head, so the general code would link the node to itself and then free it, leaving a dangling head.

Stack & Queue via SLL

Applying SLL insertion/deletion to implement a stack and a queue without a fixed array size

An array-based stack or queue (see the Unit II notes for the array stack and Unit III for the array queue) is capped by a fixed size chosen up front. Building the same structure on top of an SLL removes that cap entirely — the structure grows and shrinks one node at a time via getnode/freenode (§3.4), and never reports a false overflow.

Fig 9. The only structural difference between an SLL-backed queue and an SLL-backed stack is which end insertion happens at — deletion is always from the front (an SLL only has cheap access to its front, per §3.2).

Stack via SLL

NODE push(NODE top, int item) { return insertfront(top, item); } NODE pop(NODE top, int *val) { *val = top->info; NODE temp = top; top = top->link; freenode(temp); return top; }

Queue via SLL

Enqueue at the rear (§3.2's insertrear), dequeue from the front — this matches a queue's FIFO contract exactly, and never needs the circular-array trick (Unit III) since there's no fixed array to run out of.

NODE enqueue(NODE first, int item) { return insertrear(first, item); } NODE dequeue(NODE first, int *val) { *val = first->info; NODE temp = first; first = first->link; freenode(temp); return first; }

Reversing a Linked List

Self-learning · iterative (three pointers) and recursive approaches

Iterative: three pointers

Walk the list once, turning each node's link to point backwards. You need prev (already-reversed part), cur (node being processed) and next (saved before you overwrite cur->link, otherwise the rest of the list is lost). Time O(n), extra space O(1).

NODE* reverse(NODE *head) {
    NODE *prev = NULL, *cur = head, *next;
    while (cur != NULL) {
        next = cur->link;     /* 1. save the rest         */
        cur->link = prev;     /* 2. reverse this link     */
        prev = cur;           /* 3. advance prev          */
        cur  = next;          /* 4. advance cur           */
    }
    return prev;              /* prev is the new head     */
}

Recursive

Reverse everything after the head, then make the old second node point back to the head, and make the head the new tail. Base case: an empty list or one node is already reversed. Time O(n); extra space O(n) for the call stack (the call-stack behaviour is explained in the Unit II notes, Recursion part).

NODE* reverse_rec(NODE *head) {
    if (head == NULL || head->link == NULL) return head;   /* base case */
    NODE *rest = reverse_rec(head->link);   /* reverse the tail            */
    head->link->link = head;                /* old 2nd node points back    */
    head->link = NULL;                      /* head becomes the new tail   */
    return rest;                            /* new head from the deepest call */
}

Merging and Splitting Linked Lists

Self-learning · merge two sorted lists · split into halves or alternate nodes · joining lists

Joining (concatenating) two lists

Walk to the last node of the first list and set its link to the head of the second: O(n) for the walk, O(1) relinking. This is the quick "joining" advantage of linked lists. (With a circular list and a last pointer it becomes O(1).)

Merging two sorted lists

Compare the front nodes of both lists, attach the smaller to the result, and advance in that list. When one list runs out, attach the remainder of the other. No new nodes are created — existing nodes are just relinked. Time O(m + n).

NODE* merge(NODE *a, NODE *b) {
    NODE dummy, *t = &dummy;      /* dummy head avoids special cases */
    dummy.link = NULL;
    while (a && b) {
        if (a->data <= b->data) { t->link = a; a = a->link; }
        else                      { t->link = b; b = b->link; }
        t = t->link;
    }
    t->link = a ? a : b;           /* attach the leftover list */
    return dummy.link;
}

Example: merging 1→3→5→7 and 2→4→6→8→10 gives 1→2→3→4→5→6→7→8→10 (verified).

Splitting a list

  • Into front and back halves — use two pointers: slow moves one node, fast moves two. When fast reaches the end, slow is at the middle; cut after it. For 1→2→3→4→5→6→7 this gives 1→2→3→4 and 5→6→7 (the front gets the extra node).
  • Into alternate nodes — send nodes at positions 1, 3, 5, … to one list and 2, 4, 6, … to the other. For the same list: 1→3→5→7 and 2→4→6.
void split_half(NODE *h, NODE **front, NODE **back) {
    NODE *slow = h, *fast = h->link;      /* assumes h != NULL */
    while (fast && fast->link) { slow = slow->link; fast = fast->link->link; }
    *front = h;
    *back  = slow->link;
    slow->link = NULL;                   /* cut the list */
}

Polynomials & Sparse Matrices

Self-learning · polynomial representation and addition · sparse matrix representation

Polynomial as a linked list

Store one node per non-zero term, kept in decreasing order of exponent. Zero terms take no space, which is why a linked list suits polynomials such as x^1000 + 1.

struct poly { int coef; int exp; struct poly *link; };

Example: 5x³ + 4x² + 2x + 7 is (5,3) → (4,2) → (2,1) → (7,0).

Polynomial addition

Use two pointers, one per polynomial, comparing exponents:

  1. If exponents are equal, add the coefficients; append a term if the sum is non-zero; advance both.
  2. If one exponent is larger, copy that term to the result and advance only that pointer.
  3. When one polynomial ends, copy the remaining terms of the other.

#include <stdio.h>
#include <stdlib.h>

typedef struct poly { int coef, exp; struct poly *link; } POLY;

POLY *append(POLY *head, POLY **tail, int c, int e) {
    POLY *n = malloc(sizeof(POLY));
    n->coef = c; n->exp = e; n->link = NULL;
    if (head == NULL) head = n; else (*tail)->link = n;
    *tail = n;
    return head;
}

/* sign = +1 gives P1 + P2 ; sign = -1 gives P1 - P2 */
POLY *combine(POLY *p, POLY *q, int sign) {
    POLY *r = NULL, *t = NULL;
    while (p && q) {
        if (p->exp == q->exp) {
            int c = p->coef + sign * q->coef;
            if (c != 0) r = append(r, &t, c, p->exp);
            p = p->link; q = q->link;
        } else if (p->exp > q->exp) {
            r = append(r, &t, p->coef, p->exp); p = p->link;
        } else {
            r = append(r, &t, sign * q->coef, q->exp); q = q->link;
        }
    }
    for (; p; p = p->link) r = append(r, &t, p->coef, p->exp);
    for (; q; q = q->link) r = append(r, &t, sign * q->coef, q->exp);
    return r;
}

void show(POLY *p) {
    for (; p; p = p->link) printf("%+dx^%d ", p->coef, p->exp);
    printf("\n");
}

Sparse matrix multiplication

To compute C = A × B (A is m×n, B is n×p) without expanding either matrix, keep both as lists of non-zero elements and multiply only matching pairs. A non-zero a(i,k) can combine only with a non-zero b(k,j) in the same inner index — that is, a.col == b.row — contributing a.val × b.val to C(i,j). Several products can land on the same (i,j), so each contribution is added into an ordered result list: if node (i,j) already exists its value is increased, otherwise a node is inserted in row-major position (the ordered-insert idea of §3.3). Work done is at most (non-zeros of A) × (non-zeros of B) comparisons, against m·n·p multiplications for dense arrays.

  1. For every element a of A, walk every element b of B.
  2. If a.col == b.row, form the product a.val × b.val for position (a.row, b.col).
  3. Add it into the result list with add_term (accumulate if the position exists, else ordered insert).
  4. Result entries that cancel to 0 may be left or removed; the result is the sparse form of C.

#include <stdio.h>
#include <stdlib.h>

typedef struct elem {
    int row, col, val;
    struct elem *link;
} ELEM;

/* insert (r,c,v) into list kept in row-major order; add to value if (r,c) exists */
ELEM *add_term(ELEM *head, int r, int c, int v) {
    ELEM *prev = NULL, *cur = head;
    while (cur && (cur->row < r || (cur->row == r && cur->col < c))) {
        prev = cur; cur = cur->link;
    }
    if (cur && cur->row == r && cur->col == c) {   /* same position: accumulate */
        cur->val += v;
        return head;
    }
    ELEM *n = malloc(sizeof(ELEM));
    n->row = r; n->col = c; n->val = v; n->link = cur;
    if (prev == NULL) return n;
    prev->link = n;
    return head;
}

/* C = A x B  (A is m x n, B is n x p) */
ELEM *multiply(ELEM *A, ELEM *B) {
    ELEM *C = NULL;
    for (ELEM *a = A; a; a = a->link)
        for (ELEM *b = B; b; b = b->link)
            if (a->col == b->row)                  /* only matching inner index contributes */
                C = add_term(C, a->row, b->col, a->val * b->val);
    return C;
}

void show(const char *name, ELEM *h) {
    printf("%s:", name);
    for (; h; h = h->link) printf(" (%d,%d,%d)", h->row, h->col, h->val);
    printf("\n");
}

    B = add_term(B,2,0,1);

Multilevel (hierarchical) linked lists

A multilevel list gives each node a second pointer, child, that may point to a separate list at the next level, in addition to next. It models hierarchies such as a book's chapters → sections, or folders → files.

struct node { int data; struct node *next; struct node *child; };

Flattening: traverse the main list; whenever a node has a child list, splice that child list in between the node and its next, then continue. The result is a single-level list.

Managing dynamic collections

Linked lists suit collections whose size changes unpredictably, because nodes are added and removed without shifting elements.

  • Train composition — a doubly list of coaches; attach or detach a coach anywhere in O(1) once located.
  • Student records — nodes holding a struct student (roll, name, marks), usually kept sorted by roll number using ordered insert (§3.3).
  • Inventory — nodes of item code, quantity and price; delete a node when stock is cleared.
Exam tip For "which list would you use for …" questions: one-way traversal → SLL; cycling forever → circular; moving both ways → doubly. Always justify with the operation that dominates.

4.5

Josephus Problem (Circular Linked List)

Lab · application of lists · n people in a circle, every k-th is eliminated

The problem

n people stand in a circle numbered 1 to n. Starting from person 1, count k people (including the starting one) and eliminate the k-th; counting resumes from the next person, and the circle closes up. This continues until one person remains — the survivor. The task is to print the elimination order and the survivor. A circular singly linked list is the natural model: the last node already links back to the first, so counting "wraps around" with no special case, and eliminating a person is a single unlink (§3.5).

Algorithm

  1. Build a circular list of n nodes holding 1…n (insert each new node after last and make it the new last).
  2. Keep a pointer prev to the node before the one where counting starts (initially last, so counting starts at node 1).
  3. Advance prev by k − 1 links; now prev->link is the k-th person.
  4. Print it, set prev->link = victim->link (unlink) and free the victim. prev already precedes the next counting start.
  5. Repeat while the list has more than one node (prev->link != prev). The remaining node is the survivor.
Lab program · verified by running in C8 marks
Write a C program to solve the Josephus problem using a circular linked list for n = 7 and k = 3.
Answer — full program
#include <stdio.h>
#include <stdlib.h>
typedef struct node { int data; struct node *link; } NODE;

int main(void) {
    int n = 7, k = 3;
    NODE *last = NULL;                       /* build circular list 1..n */
    for (int i = 1; i <= n; i++) {
        NODE *t = malloc(sizeof(NODE)); t->data = i;
        if (!last) { t->link = t; } else { t->link = last->link; last->link = t; }
        last = t;
    }
    NODE *prev = last;                       /* prev precedes the counting start (node 1) */
    printf("Elimination order:");
    while (prev->link != prev) {
        for (int c = 1; c < k; c++) prev = prev->link;   /* move k-1 steps */
        NODE *victim = prev->link;
        printf(" %d", victim->data);
        prev->link = victim->link;           /* unlink */
        free(victim);
    }
    printf("\nSurvivor: %d\n", prev->data);
    return 0;
}

4.6

Detect and Remove a Loop in a Linked List

Lab · application of lists · Floyd's tortoise-and-hare, finding the loop start, breaking the loop

What is a loop?

A loop (cycle) exists when some node's link points back to an earlier node instead of ending in NULL — usually through a pointer bug. A traversal while (p != NULL) then never terminates. Two things must be done: detect it, and if present remove it by setting the offending link to NULL.

Detection: Floyd's tortoise-and-hare (O(1) space)

Use two pointers from the head: slow moves one node per step, fast moves two. If the list ends, fast reaches NULL and there is no loop. If there is a loop, both end up inside it and fast gains one node per step on slow, so they must meet. Time O(n), extra space O(1). The alternative — storing every visited node address in a hash set or marking nodes — uses O(n) extra space, which is why Floyd's method is preferred.

Lab program (Part A) · verified4 marks
Write a function to detect the cycle in a linked list.
Answer
int has_cycle(NODE *head) {
    NODE *slow = head, *fast = head;
    while (fast && fast->link) {          /* fast checked first: it reaches NULL first */
        slow = slow->link;                /* 1 step  */
        fast = fast->link->link;          /* 2 steps */
        if (slow == fast) return 1;       /* they meet inside a loop */
    }
    return 0;                             /* fast fell off the end: no loop */
}

Finding the loop's starting node

Let μ be the number of nodes before the loop and λ the loop length. Suppose slow and fast meet at a point x nodes past the loop start. Slow has travelled μ + x; fast, twice as far, 2(μ + x), which equals μ + x plus some whole number of laps: μ + x = m·λ. Hence μ = m·λ − x: walking μ steps from the meeting point lands exactly on the loop start. So after the meeting, restart one pointer at the head and move both pointers one step at a time; they meet at the loop's first node.

Removing the loop

With the loop start s known, walk from s until p->link == s; that p is the last node of the loop. Setting p->link = NULL turns the list back into a plain list. (If the loop start is the head itself, the same walk still works.)

#include <stdlib.h>
typedef struct node { int data; struct node *link; } NODE;

NODE *push_back(NODE *head, NODE **tail, int v) {
    NODE *n = malloc(sizeof(NODE)); n->data = v; n->link = NULL;
    if (!head) head = n; else (*tail)->link = n;
    *tail = n; return head;
}
int has_cycle(NODE *head) {
    NODE *slow = head, *fast = head;
    while (fast && fast->link) {
        slow = slow->link; fast = fast->link->link;
        if (slow == fast) return 1;
    }
    return 0;
}
NODE *loop_start(NODE *head) {
    NODE *slow = head, *fast = head;
    while (fast && fast->link) {
        slow = slow->link; fast = fast->link->link;
        if (slow == fast) {
            printf("meeting node = %d\n", slow->data);
            slow = head;                       /* restart one pointer at head */
            while (slow != fast) { slow = slow->link; fast = fast->link; }
            return slow;
        }
    }
    return NULL;
}
int remove_loop(NODE *head) {
    NODE *s = loop_start(head);
    if (!s) return 0;
    NODE *p = s;
    while (p->link != s) p = p->link;          /* last node of the loop */
    p->link = NULL;
    return 1;
}

    int len = 1; for (NODE *p = s->link; p != s; p = p->link) len++;
    printf("loop length %d\n", len);
    remove_loop(h);
    printf("after removal cycle? %d\nlist:", has_cycle(h));
    for (NODE *p = h; p; p = p->link) printf(" %d", p->data);
    printf("\n");
    return 0;
}
